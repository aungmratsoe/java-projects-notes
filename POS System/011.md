# ကော်ဖီဆိုင် POS စနစ် - Database Design (Java, Swing)

Java Swing ကို frontend (GUI) အနေနဲ့ သုံးပြီး၊ backend database အနေနဲ့ MySQL/SQLite ကို JDBC နဲ့ ချိတ်ဆက်တဲ့ POS စနစ်တစ်ခုအတွက် database design ကို ရှင်းပြပေးပါမယ်။

## ၁။ လိုအပ်တဲ့ Table များ (Entities)

**categories** (အမျိုးအစားများ - ဥပမာ Coffee, Tea, Pastry)

- category_id (PK)
- category_name

**products** (ကုန်ပစ္စည်း/မီနူး)

- product_id (PK)
- category_id (FK → categories)
- product_name
- price
- stock_qty (သို့) is_available
- image_path (optional)

**customers** (ဖောက်သည် - membership/loyalty ရှိရင်)

- customer_id (PK)
- name
- phone
- loyalty_points

**employees** (ဝန်ထမ်း/ဝန်ဆောင်သူ)

- employee_id (PK)
- name
- username
- password_hash
- role (admin, cashier, barista)

**orders** (မှာယူမှု)

- order_id (PK)
- customer_id (FK, nullable)
- employee_id (FK)
- order_date (datetime)
- order_type (dine-in, takeaway)
- table_number (nullable)
- total_amount
- status (pending, completed, cancelled)

**order_items** (မှာယူမှုထဲက item တစ်ခုချင်းစီ)

- order_item_id (PK)
- order_id (FK → orders)
- product_id (FK → products)
- quantity
- unit_price
- subtotal

**payments** (ငွေပေးချေမှု)

- payment_id (PK)
- order_id (FK → orders)
- payment_method (cash, card, mobile pay)
- amount_paid
- payment_date

**inventory_transactions** (ကုန်ပစ္စည်း ဝင်/ထွက် မှတ်တမ်း - optional, ကြီးမားတဲ့စနစ်အတွက်)

- transaction_id (PK)
- product_id (FK)
- change_qty
- reason (restock, sale, waste)
- transaction_date

## ၂။ Relationship (ဆက်နွယ်မှု) များ

- **categories → products**: One-to-Many (တစ် category မှာ product အများကြီးရှိနိုင်)
- **orders → order_items**: One-to-Many (order တစ်ခုမှာ item အများကြီး)
- **products → order_items**: One-to-Many (product တစ်ခုကို order များစွာမှာ ထည့်နိုင်)
- **orders → payments**: One-to-One (သို့) One-to-Many (split payment ရှိရင်)
- **customers → orders**: One-to-Many
- **employees → orders**: One-to-Many (ဘယ်ဝန်ထမ်းက order ကိုင်တွယ်လဲ)

## ၃။ ER Diagram (Text ပုံစံ)

```
categories ──1:N── products ──1:N── order_items ──N:1── orders ──N:1── customers
                                                              │
                                                              ├──N:1── employees
                                                              │
                                                              └──1:N── payments
```

## ၄။ Java Swing နဲ့ ချိတ်ဆက်ပုံ (Architecture)

**Layered Architecture** သုံးဖို့ အကြံပြုပါတယ်:

1. **Model layer** - `Product.java`, `Order.java`, `OrderItem.java` စတဲ့ POJO classes (database row တစ်ခုချင်းစီကို object အနေနဲ့ ကိုယ်စားပြု)
2. **DAO layer** (Data Access Object) - `ProductDAO.java`, `OrderDAO.java` - SQL query တွေကို JDBC နဲ့ ရေးမယ့် နေရာ
3. **Service layer** - business logic (ဥပမာ - stock လျော့တာ၊ total price တွက်တာ)
4. **View layer** - Swing GUI (JFrame, JTable, JButton) - menu ပြတာ၊ order ထည့်တာ

## ၅။ Database ရွေးချယ်ရေး

- **အသေးစား/single-computer**: SQLite (JDBC driver: `sqlite-jdbc`) - ဖိုင်တစ်ခုတည်း၊ setup လွယ်
- **ဆိုင်ကြီး/multi-terminal**: MySQL - server-based, terminal အများကြီးက တစ်ပြိုင်နက် ဝင်နိုင်

## ၆။ အရေးကြီးတဲ့ Design အချက်များ

- `order_items` မှာ `unit_price` ကို သိမ်းထားသင့်တယ် - နောက်မှ product price ပြောင်းရင်တောင် အရင်order ရဲ့ ဈေးနှုန်းအမှန် မပျောက်စေဖို့
- `stock_qty` ကို order confirm ဖြစ်တာနဲ့ trigger သို့မဟုတ် code logic နဲ့ auto-update လုပ်ရမယ်
- Transaction (JDBC `Connection.setAutoCommit(false)`) သုံးပြီး order + order_items + payment ကို atomic operation အဖြစ် save လုပ်သင့်တယ် (တစ်ခုမအောင်မြင်ရင် အားလုံး rollback)
