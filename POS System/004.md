## Connection Pool (HikariCP) ကို ဘာကြောင့် သုံးရလဲ

### Pool မသုံးဘဲ လုပ်ရင် ဘာဖြစ်လဲ — အရင်ဆုံး ပြဿနာကို ကြည့်ရအောင်

Database connection တစ်ခု "create" လုပ်တာဆိုတာ light-weight operation မဟုတ်ပါဘူး။ Java က MySQL ဆီ connection အသစ်တစ်ခု တောင်းတိုင်း နောက်ကွယ်မှာ ဒီလို steps တွေ ဖြစ်ပျက်နေပါတယ်:

```
1. TCP socket ဖွင့် (network handshake — client ↔ MySQL server)
2. MySQL authentication (username/password verify)
3. Session initialize (MySQL server side memory allocate)
4. SSL negotiation (encrypt ဖွင့်ထားရင်)
```

ဒါက **milliseconds ဆယ်ဂဏန်း** ကြာနိုင်ပါတယ် — Object တစ်ခု `new` လုပ်တာနဲ့ လုံးဝမတူပါဘူး၊ ကွန်ပျူတာနှစ်လုံးကြား network round-trip အများကြီး ပါဝင်တာပါ။

Pool မသုံးဘဲ Cafe POS မှာ code ရေးမယ်ဆိုပါစို့:

```java
// Cashier က "Add to cart" click တိုင်း, product click တိုင်း
public Product getProduct(int id) {
    Connection conn = DriverManager.getConnection(URL, USER, PASS); // ← 20-50ms ကြာနိုင်တယ်
    // query...
    conn.close();
    return product;
}
```

Cashier တစ်ယောက်က coffee menu ကို scroll ကြည့်ရုံနဲ့တင် product query 10 ခါ run ရင် — connection အသစ် 10 ခု create + close ဖြစ်နေမယ်။ POS screen က **slow/laggy** ဖြစ်သွားမယ် — button click တိုင်း "ခဏစောင့်ပါ" ဆိုသလို ခံစားရမယ်။

ဒါ့အပြင် ပိုဆိုးတာက — Cashier 3-4 ယောက် တစ်ပြိုင်နက် POS သုံးနေရင် (multi-user environment), connection တွေ အများကြီး ဖွင့်နေမယ်။ MySQL server ကိုယ်တိုင်မှာလည်း **max_connections limit** ရှိပါတယ် (default 151 ဖြစ်လေ့ရှိတယ်) — connection အများကြီး ဖွင့်ပြီး မပိတ်ဘဲ ကျန်ခဲ့ရင် (code ထဲမှာ `conn.close()` မမေ့ရင်တောင် exception ဖြစ်ရင် leak ဖြစ်တတ်တယ်) — တစ်ချိန်ချိန်မှာ **"Too many connections"** error တက်ပြီး POS system တစ်ခုလုံး ရပ်သွားနိုင်ပါတယ်။

---

### Connection Pool ရဲ့ Core Idea — "ပြန်သုံးမယ် (Reuse)"

Pool ရဲ့ concept က ရိုးရှင်းပါတယ်: **Connection တွေကို app စချိန်မှာ အတည်ဖွင့်ပြီး ကြိုသိမ်းထားမယ်, "ပိတ်" မယ့်အစား "pool ထဲ ပြန်ထည့်" မယ်။**

```
App စတယ်
  → HikariCP က connection 10 ခု ကြိုဖွင့်ထားတယ် (pool ထဲ ထားတယ်)

Cashier က product query လိုချင်တယ်
  → pool ကနေ connection "borrow" လုပ်တယ် (create မလုပ်တော့ဘူး, ready-made ကို ယူတာ)
  → query run
  → conn.close() ခေါ်ပေမယ့် ဒါက အမှန်တကယ် close မဟုတ်ဘူး
     → HikariCP က intercept လုပ်ပြီး "pool ထဲ ပြန်ထည့်" လိုက်တယ် (available ပြန်ဖြစ်)

နောက် request တစ်ခု လာရင်
  → connection အသစ်ဖွင့်စရာ မလိုဘူး, pool ထဲက available connection ကို ချက်ချင်း ယူသုံးတယ်
```

ဒီနည်းနဲ့ "connection ဖွင့်ခြင်း" ရဲ့ ကုန်ကျစရိတ် (20-50ms) ကို **တစ်ခါတည်း app start မှာပဲ** ပေးရတော့တာပါ — Cashier click တိုင်း ပေးစရာမလိုတော့ဘူး။ Query တစ်ခုစီက **~1ms အောက်** မှာ connection ရသွားတယ် (pool ထဲက ready-made ကို ယူတာဖြစ်လို့)။

---

### HikariCP ကို ဘာကြောင့် အသုံးများလဲ (technical reason)

Java မှာ connection pool library တော်တော်များများ ရှိပါတယ် (Apache DBCP, C3P0, HikariCP)။ HikariCP ကို modern project တွေမှာ default choice အဖြစ် သုံးကြတဲ့အကြောင်းရင်း:

1. **Performance** — bytecode level optimization တွေ လုပ်ထားတယ်, benchmark မှာ pool library တွေထဲက fastest ဖြစ်တယ်
2. **Lightweight** — dependency အနည်းငယ်ပဲ ပါတယ်
3. **Leak detection** — connection ကို borrow လုပ်ပြီး ကြာကြာမပြန်ရင် (code ထဲက `close()` ခေါ်ဖို့ မေ့ခဲ့ရင်) warning log ထုတ်ပေးတယ် — POS project ကြီးမှာ bug ရှာရာမှာ အထောက်အကူများတယ်
4. **Spring Boot default** — industry standard အဖြစ် widely adopted ဖြစ်တယ်

### Cafe POS App မှာ Pool Size ဘယ်လောက် သင့်လျော်လဲ (Real concept)

Pool size ကို "များများကောင်း" လို့ မထင်သင့်ပါဘူး — ဒါက core concept တစ်ခုပါ:

- Pool size **အလွန်ကြီး** ရင် → MySQL server side memory/resource ကုန်တယ်, thread contention ဖြစ်တတ်တယ်
- Pool size **အလွန်သေး** ရင် → Cashier 3-4 ယောက် တစ်ပြိုင်နက်သုံးရင် connection မရလို့ queue မှာ စောင့်ရတယ်

Single Cafe (POS terminal 2-3 လုံးလောက်) အတွက်ဆိုရင် **pool size 5-10** လောက်က လုံလောက်ပါတယ်။ HikariCP config နမူနာ:

```java
HikariConfig config = new HikariConfig();
config.setJdbcUrl("jdbc:mysql://localhost:3306/cafe_pos");
config.setUsername("root");
config.setPassword("yourpassword");
config.setMaximumPoolSize(10);      // pool ထဲ connection အများဆုံး 10 ခု
config.setMinimumIdle(2);           // idle time မှာတောင် connection 2 ခု ကြိုဖွင့်ထားမယ်
config.setConnectionTimeout(30000); // pool ကုန်နေရင် 30 sec စောင့်, ပြီးရင် exception
config.setIdleTimeout(600000);      // 10 မိနစ် idle နေရင် connection ကို ပိတ်

HikariDataSource dataSource = new HikariDataSource(config);
```

DAO layer မှာ သုံးပုံ (Singleton pattern သုံးလေ့ရှိတယ်, App တစ်ခုလုံးမှာ DataSource တစ်ခုတည်းပဲ ရှိသင့်တယ်):

```java
public class DatabaseConnection {
    private static HikariDataSource dataSource;

    static {
        HikariConfig config = new HikariConfig();
        // ... config အထက်ကအတိုင်း
        dataSource = new HikariDataSource(config);
    }

    public static Connection getConnection() throws SQLException {
        return dataSource.getConnection();  // pool ကနေ borrow
    }
}
```

**သတိထားရမယ့်အချက်**: `DataSource` object ကို app တစ်ခုလုံးမှာ **တစ်ခုတည်းပဲ** create လုပ်ရပါမယ် (static field / Singleton) — DAO method တစ်ခုချင်းစီမှာ `new HikariDataSource()` ဆိုပြီး ထပ်ဆင့် create လုပ်ရင် pool ချင်း အများကြီး ဖြစ်နေမယ့်, ဒါဆို pool ရဲ့ အဓိပ္ပာယ်ကို လုံးဝ ဆုံးရှုံးသွားမှာပါ။

---

**အနှစ်ချုပ်**: Connection creation က "ကုန်ကျစရိတ်များတဲ့" operation ဖြစ်လို့, pool က connection တွေကို ကြိုဖွင့်ပြီး reuse လုပ်တယ် → POS screen response မြန်တယ်, MySQL server ကို connection ဖွင့်/ပိတ် ခဏခဏ မဖိစီးစေဘူး, connection leak ဖြစ်ရင်လည်း detect လုပ်နိုင်တယ်။

ဆက်ချင်တာ ရွေးပါ:

1. **try-with-resources** — pool ကနေ ယူထားတဲ့ connection ကို ဘယ်လို safely ပြန်ပေးရမလဲ (leak လုံးဝမဖြစ်အောင်)
2. **Isolation Level** (READ_COMMITTED vs SERIALIZABLE) — POS မှာ ဘယ် level သင့်လျော်လဲ
3. Layered Architecture concept ကို ဆက်လေ့လာမယ်
4.

To use **HikariCP** (a high-performance, lightweight JDBC connection pool) in a Java Swing Maven project, you need to add the HikariCP dependency along with your chosen database driver (e.g., MySQL, PostgreSQL, or SQLite) to your `pom.xml`, and then set up a connection manager.

  

### Step 1: Add Dependencies to `pom.xml`

Add the HikariCP dependency and your database driver (MySQL is used in this example) to your project's `pom.xml` file:

  

XML

```xml
<dependencies>
    <!-- HikariCP Connection Pool -->
    <dependency>
        <groupId>com.zaxxer</groupId>
        <artifactId>HikariCP</artifactId>
        <version>6.2.1</version>
    </dependency>

    <!-- Example: MySQL JDBC Driver (replace with your DB driver) -->
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
        <version>9.0.0</version>
    </dependency>
</dependencies>
```

### Step 2: Create a Database Connection Manager Utility

Create a utility class (e.g., `DatabaseManager.java`) to initialize the connection pool once when your application starts up.

  

Java

```java
import com.zaxxer.hikari.HikariConfig;
import com.zaxxer.hikari.HikariDataSource;

import java.sql.Connection;
import java.sql.SQLException;

public class DatabaseManager {
    private static final HikariDataSource dataSource;

    static {
        HikariConfig config = new HikariConfig();
        config.setJdbcUrl("jdbc:mysql://localhost:3306/your_database_name");
        config.setUsername("your_username");
        config.setPassword("your_password");
        
        // Optional Pool Tuning for Desktop Apps
        config.setMaximumPoolSize(5); // Swing apps usually need fewer connections
        config.setMinimumIdle(2);
        config.setIdleTimeout(30000);
        config.setConnectionTimeout(10000);

        dataSource = new HikariDataSource(config);
    }

    // Method to fetch a connection from the pool
    public static Connection getConnection() throws SQLException {
        return dataSource.getConnection();
    }

    // Shutdown pool when the app closes
    public static void closePool() {
        if (dataSource != null && !dataSource.isClosed()) {
            dataSource.close();
        }
    }
}
```

### Step 3: Use Connections Safely in Swing (Crucial!)

In a Java Swing application, **never run database queries directly on the Event Dispatch Thread (EDT)**, or your UI will freeze/hang while waiting for the network or disk response.

  

Instead, use `SwingWorker` to perform database operations in the background:

  

Java

```java
import javax.swing.*;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class UserDataLoader {

    public static void loadDataAsync(JTable table) {
        // SwingWorker runs background tasks off the EDT
        SwingWorker<Void, Void> worker = new SwingWorker<>() {
            @Override
            protected Void doInBackground() throws Exception {
                // Fetch connection from HikariCP pool and query database
                String sql = "SELECT id, name, email FROM users";
                
                // try-with-resources automatically returns connection to the pool
                try (Connection conn = DatabaseManager.getConnection();
                     PreparedStatement stmt = conn.prepareStatement(sql);
                     ResultSet rs = stmt.executeQuery()) {

                    while (rs.next()) {
                        int id = rs.getInt("id");
                        String name = rs.getString("name");
                        // Process your data or add rows to a DefaultTableModel
                    }
                } catch (SQLException e) {
                    e.printStackTrace();
                }
                return null;
            }

            @Override
            protected void done() {
                // This runs back on the EDT once the query finishes
                // Safe to update UI components here (e.g., table.setModel(...))
            }
        };

        worker.execute();
    }
}
```

Here is the complete, production-ready code setup using an external `database.properties` file so your credentials stay safe and out of your source code.

  

### Step 1: Create `database.properties`

Create this file inside your project's **`src/main/resources/`** folder:

  

Properties

```
db.url=jdbc:mysql://localhost:3306/your_database_name
db.user=root
db.password=your_password
```

_(Remember to add `database.properties` to your `.gitignore` file if your project is open-source or on GitHub!)_

  

### Step 2: Create `DatabaseManager.java`

Create a utility class anywhere in your source packages (e.g., `com.yourname.database.DatabaseManager.java`):

  

Java

```
package com.yourname.database;

import com.zaxxer.hikari.HikariConfig;
import com.zaxxer.hikari.HikariDataSource;

import java.io.IOException;
import java.io.InputStream;
import java.sql.Connection;
import java.sql.SQLException;
import java.util.Properties;

public class DatabaseManager {
    private static final HikariDataSource dataSource;

    static {
        Properties props = new Properties();
        
        // Load database.properties safely from src/main/resources
        try (InputStream input = DatabaseManager.class.getClassLoader().getResourceAsStream("database.properties")) {
            if (input == null) {
                throw new RuntimeException("Error: 'database.properties' not found in src/main/resources!");
            }
            props.load(input);
        } catch (IOException ex) {
            throw new RuntimeException("Error: Failed to load database configuration file.", ex);
        }

        // Configure HikariCP
        HikariConfig config = new HikariConfig();
        config.setJdbcUrl(props.getProperty("db.url"));
        config.setUsername(props.getProperty("db.user"));
        config.setPassword(props.getProperty("db.password"));

        // Optimized pool settings for a Desktop/Swing application
        config.setMaximumPoolSize(5);
        config.setMinimumIdle(2);
        config.setIdleTimeout(30000); // 30 seconds
        config.setConnectionTimeout(10000); // 10 seconds

        dataSource = new HikariDataSource(config);
    }

    // Private constructor to prevent object creation
    private DatabaseManager() {}

    /**
     * Fetch a active connection from the pool.
     * Always use this inside a try-with-resources block so connections return to the pool automatically!
     */
    public static Connection getConnection() throws SQLException {
        return dataSource.getConnection();
    }

    /**
     * Closes the connection pool entirely. Call this when your application exits.
     */
    public static void closePool() {
        if (dataSource != null && !dataSource.isClosed()) {
            dataSource.close();
        }
    }
}
```

### Step 3: How to Use It in Your Main Swing Window (`MainFrame.java`)

Here is an example of how to initialize your main frame, safely query the database in the background using `SwingWorker`, and clean up the connection pool when the application closes:

Java

```
import com.yourname.database.DatabaseManager;

import javax.swing.*;
import java.awt.event.WindowAdapter;
import java.awt.event.WindowEvent;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class MainFrame extends JFrame {

    public MainFrame() {
        setTitle("Swing Database App");
        setSize(500, 400);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);

        // 1. Ensure the HikariCP pool shuts down cleanly when the window closes
        this.addWindowListener(new WindowAdapter() {
            @Override
            public void windowClosing(WindowEvent e) {
                System.out.println("Closing database connection pool...");
                DatabaseManager.closePool();
            }
        });

        // Test loading data on startup
        loadDataAsync();
    }

    private void loadDataAsync() {
        // 2. Always perform database queries off the Event Dispatch Thread (EDT)
        SwingWorker<Void, Void> worker = new SwingWorker<>() {
            @Override
            protected Void doInBackground() throws Exception {
                String sql = "SELECT id, name FROM users";

                // try-with-resources automatically closes statements and returns the connection to HikariCP
                try (Connection conn = DatabaseManager.getConnection();
                     PreparedStatement stmt = conn.prepareStatement(sql);
                     ResultSet rs = stmt.executeQuery()) {

                    while (rs.next()) {
                        int id = rs.getInt("id");
                        String name = rs.getString("name");
                        System.out.println("Loaded User -> ID: " + id + ", Name: " + name);
                    }

                } catch (SQLException e) {
                    e.printStackTrace();
                }
                return null;
            }

            @Override
            protected void done() {
                // 3. Update your UI components here back on the EDT once the query finishes
                System.out.println("Data loading completed!");
            }
        };

        worker.execute();
    }

    public static void main(String[] args) {
        // Run UI creation on the EDT
        SwingUtilities.invokeLater(() -> {
            new MainFrame().setVisible(true);
        });
    }
}
```
