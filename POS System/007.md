# Session/State Management — Cafe POS အတွက် (Login Session, Current User, Shift Tracking)

ဒီသင်ခန်းစာမှာ desktop application (Java Swing) ရဲ့ session/state management ကို deep-dive လုပ်ကြမယ်။ Web application တွေမှာ session ဆိုတာ server-side cookie/token နဲ့ ချိတ်ရတယ်၊ ဒါပေမယ့် desktop app မှာတော့ **တစ်ခုတည်းသော process (JVM)** ထဲမှာပဲ run နေတာမို့ concept က ပိုရိုးရှင်းပေမယ့် design ကို သေချာစဉ်းစားဖို့ လိုတယ်။

## ၁. Desktop App မှာ "Session" ဆိုတာ ဘာလဲ

Web app တစ်ခုမှာ user ၅ ယောက်က server တစ်ခုတည်းကို တခြားစီ hit လုပ်တာမို့ "ဘယ်သူက ဘယ်သူလဲ" ခွဲဖို့ token/session-id လိုတယ်။ Desktop POS app မှာတော့ **application တစ်ခုကို operator/cashier တစ်ယောက်ချင်းစီက run** တာမို့:

- Session = "ဒီ app instance ကို ဘယ် user login ဝင်ထားလဲ" ဆိုတဲ့ **runtime state**
- Server session လိုမျိုး expire/timeout logic လိုချင်ရင်ရ၊ မလိုချင်ရင်လည်းရ (POS မှာတော့ shift-based timeout လုပ်လေ့ရှိတယ်)

## ၂. Design Pattern: SessionManager (Singleton)

App တစ်ခုလုံးမှာ "current user" ဆိုတာ တစ်ခုတည်းပဲ ရှိသင့်တယ် — ဒါကြောင့် **Singleton pattern** သုံးလေ့ရှိတယ်။

```java
public class SessionManager {
    private static SessionManager instance;
    
    private User currentUser;
    private Shift currentShift;
    private LocalDateTime loginTime;
    
    private SessionManager() { } // private constructor
    
    public static SessionManager getInstance() {
        if (instance == null) {
            instance = new SessionManager();
        }
        return instance;
    }
    
    public void login(User user) {
        this.currentUser = user;
        this.loginTime = LocalDateTime.now();
    }
    
    public void logout() {
        this.currentUser = null;
        this.currentShift = null;
    }
    
    public User getCurrentUser() {
        return currentUser;
    }
    
    public boolean isLoggedIn() {
        return currentUser != null;
    }
}
```

**ဘာကြောင့် Singleton လဲ** — POS window (Sales screen, Inventory screen, Report screen) တွေအားလုံးက "ဘယ်သူက login ဝင်ထားလဲ" ဆိုတာကို သိချင်တယ်။ Constructor parameter နဲ့ user object ကို screen တိုင်း pass လုပ်နေရင် code ရှုပ်သွားမယ်။ `SessionManager.getInstance().getCurrentUser()` နဲ့ ဘယ်နေရာကမဆို ခေါ်လို့ရအောင် ဒီ pattern သုံးတယ်။

> **သတိပေးချက်**: Singleton ကို overuse လုပ်ရင် unit test လုပ်ရခက်တယ် (global state ဖြစ်နေလို့)။ POS app လိုမျိုး scale သေးတဲ့ desktop app အတွက်တော့ practical solution ပဲ။ ကျယ်ကျယ်ပြန့်ပြန့် enterprise app ဆိုရင် Dependency Injection (Spring, Guice) သုံးလေ့ရှိတယ်။

## ၄. Shift Tracking — ဒါက POS-specific concept

Cafe POS မှာ "shift" ဆိုတာ cashier တစ်ယောက် register ဖွင့်ကတည်းက ပိတ်တဲ့အထိ time period ကို ဆိုလိုတယ်။ Shift ဆိုတာ **user session ထက် lifecycle ပိုရှည်တဲ့ separate state** ဖြစ်တယ် — user တစ်ယောက်တည်းက shift အလုပ်ပိတ်ဖို့ logout/login ထပ်လုပ်နိုင်တယ်။

```java
public class Shift {
    private int shiftId;
    private User cashier;
    private LocalDateTime startTime;
    private LocalDateTime endTime;
    private BigDecimal openingCashFloat;
    private BigDecimal closingCashCounted;
    private ShiftStatus status; // OPEN, CLOSED
    
    // getters/setters...
}
```

**Shift ရဲ့ typical flow**:

1. **Open Shift** — cashier login ဝင်ပြီး register ဖွင့်တဲ့အချိန်၊ opening cash float (ဥပမာ - drawer ထဲက starting cash ¥50,000) ကို enter လုပ်တယ်
2. **During Shift** — sales transaction တွေအားလုံးကို ဒီ `shiftId` နဲ့ ချိတ်ထား (traceability အတွက်)
3. **Close Shift** — cashier က register ပိတ်တဲ့အခါ actual cash count ကို ရိုက်ထည့်တယ်၊ system က expected total (opening float + sales) နဲ့ ယှဉ်ပြီး over/short ရှိမရှိ တွက်ပေးတယ်

```java
public class SessionManager {
    // ... user fields အထက်ကအတိုင်း
    
    private Shift currentShift;
    
    public void openShift(BigDecimal openingFloat) {
        Shift shift = new Shift();
        shift.setCashier(currentUser);
        shift.setStartTime(LocalDateTime.now());
        shift.setOpeningCashFloat(openingFloat);
        shift.setStatus(ShiftStatus.OPEN);
        // database ထဲ save လုပ်ပြီး shiftId ရအောင်လုပ် ...
        this.currentShift = shift;
    }
    
    public ShiftSummary closeShift(BigDecimal closingCashCounted) {
        currentShift.setEndTime(LocalDateTime.now());
        currentShift.setClosingCashCounted(closingCashCounted);
        currentShift.setStatus(ShiftStatus.CLOSED);
        
        BigDecimal expected = currentShift.getOpeningCashFloat()
                .add(getTotalSalesForShift(currentShift.getShiftId()));
        BigDecimal variance = closingCashCounted.subtract(expected);
        
        // database update, generate report...
        Shift closed = this.currentShift;
        this.currentShift = null;
        
        return new ShiftSummary(closed, expected, variance);
    }
    
    public Shift getCurrentShift() {
        return currentShift;
    }
}
```

## ၅. User Session vs Shift — ဘာကွာလဲ

### User Session vs Shift

|အချက်|User Session|Shift|
|---|---|---|
|Scope|ဘယ်သူ Login ဝင်ထားလဲ|ဘယ် Register ဖွင့်ထားလဲ|
|Lifecycle|Login → Logout|Open Shift → Close Shift|
|ချိတ်ဆက်ပုံ|1 User = 1 Active Session (တစ်ချိန်တည်း)|Shift ရဲ့ Owner က User ဖြစ်ပေမယ့် Shift Object က Database မှာ Persist ဖြစ်ရမယ်|
|Purpose|Authorization, Authentication, Permission Control|Cash Reconciliation, Sales Report Grouping, Register Accounting|

Design အနေနဲ့ user တစ်ယောက် logout လုပ်ရင်တောင် shift က open ဆက်ရှိနေနိုင်တယ် (ဥပမာ - break time logout၊ ပြန်ဝင်ရင် shift ဆက်ထားရင် login screen ကနေ "resume shift" လုပ်နိုင်အောင်)။ ဒါကြောင့် **Shift object ကို User object ထက် independent** ဖြစ်အောင် design လုပ်ထားတာ။

## ၆. UI Layer (Swing) နဲ့ ချိတ်ဆက်ပုံ

MigLayout နဲ့ login form တည်ဆောက်ထားပြီးသားဆိုရင်, login button action listener ထဲမှာ:

```java
btnLogin.addActionListener(e -> {
    User authenticatedUser = authService.authenticate(username, password);
    if (authenticatedUser != null) {
        SessionManager.getInstance().login(authenticatedUser);
        // shift ရှိပြီးသားလား စစ်, မရှိရင် open shift dialog ပြ
        if (SessionManager.getInstance().getCurrentShift() == null) {
            showOpenShiftDialog();
        }
        navigateToMainPOSScreen();
    } else {
        showError("Username or password incorrect");
    }
});
```

Main POS screen ရဲ့ header panel မှာ `SessionManager.getInstance().getCurrentUser().getFullName()` ကို label တစ်ခုနဲ့ ပြထားလို့ရတယ် (ဥပမာ - "Cashier: Aye Aye | Shift #23 opened 08:00 AM")။
