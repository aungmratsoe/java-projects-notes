## `@SerializedName` နဲ့ Custom Field Mapping

### ၁။ ဘာကြောင့်လိုအပ်လဲ

Java coding convention မှာ field name တွေကို `camelCase` (studentId, phoneNumber) နဲ့ရေးလေ့ရှိပေမယ့်၊ JSON data တွေက API တစ်ခုနဲ့တစ်ခု convention မတူတတ်ပါဘူး — `snake_case` (student_id), ဒါမှမဟုတ် လုံးဝမတူတဲ့ key name (`sid`) စသဖြင့် ရှိနိုင်ပါတယ်။ Gson ရဲ့ default behavior က field name ကို JSON key name အနေနဲ့ တိုက်ရိုက်တိုက်ဆိုင်ပါတယ် (case-sensitive)၊ မတူရင် value ကို `null` ပြန်ပေးလိမ့်မယ်။ ဒါကြောင့် `@SerializedName` annotation နဲ့ mapping ကို manual သတ်မှတ်ပေးရပါတယ်။

### ၂။ အခြေခံအသုံးပြုပုံ

```java
import com.google.gson.annotations.SerializedName;

public class Student {

    @SerializedName("student_id")
    private String studentId;

    @SerializedName("full_name")
    private String name;

    @SerializedName("age")
    private int age;

    // ... constructors, getters, setters
}
```

JSON ဘက်ကလာတဲ့ data:

```json
{
  "student_id": "STU001",
  "full_name": "Aung Aung",
  "age": 20
}
```

```java
Student student = gson.fromJson(jsonString, Student.class);
System.out.println(student.getStudentId()); // "STU001" ရပါတယ် - snake_case key ကို camelCase field ထဲကို ဆွဲထည့်ပေးတယ်
```

Serialize လုပ်တဲ့အခါလည်း အလိုအလျောက် `student_id`, `full_name` format အနေနဲ့ output ထွက်ပါလိမ့်မယ် — two-way (serialize/deserialize) နှစ်ခုစလုံးအတွက် annotation တစ်ခုတည်းနဲ့ အလုပ်ဖြစ်ပါတယ်။

### ၃။ Alternate Names (Fallback Key)

တစ်ခါတစ်လေ API version ပြောင်းလာရင် key name ပြောင်းသွားတတ်ပါတယ် (v1 က `student_id`, v2 က `studentId` ဆိုပါစို့)။ Deserialize လုပ်တဲ့အခါ key name ဟောင်း/သစ် နှစ်မျိုးလုံးကို လက်ခံချင်ရင် array ပုံစံနဲ့ ပေးလို့ရပါတယ်:

```java
@SerializedName(value = "student_id", alternate = {"studentId", "sid"})
private String studentId;
```

**Note**: `alternate` က deserialize (JSON → Java) အတွက်သာ အလုပ်လုပ်ပါတယ်။ Serialize (Java → JSON) လုပ်တဲ့အခါတော့ `value` ထဲမှာ ထည့်ထားတဲ့ primary name (`student_id`) ကိုပဲ output အနေနဲ့ ထုတ်ပေးပါတယ်။

### ၄။ Nested Object Mapping ဥပမာ

```java
public class Student {
    @SerializedName("student_id")
    private String studentId;

    @SerializedName("contact_info")
    private ContactInfo contactInfo;
}

public class ContactInfo {
    @SerializedName("phone_number")
    private String phoneNumber;

    @SerializedName("email_address")
    private String email;
}
```

Gson က nested object ထဲအထိ automatic ဆင်းသွားပြီး annotation ကို respect လုပ်ပါတယ် — extra config လုပ်ရန်မလိုပါ။

### ၅။ Field ကို လုံးဝချန်ချင်ရင် (`@Expose`)

Field အချို့ကို serialize/deserialize လုံးဝ မလုပ်စေချင်ရင် `transient` keyword (သို့) `@Expose` annotation သုံးနိုင်ပါတယ်:

```java
public class Student {
    @SerializedName("student_id")
    private String studentId;

    private transient String tempPassword; // JSON ထဲ လုံးဝမပါတော့ဘူး
}
```

`transient` က Java built-in keyword ဖြစ်ပြီး Gson က default အနေနဲ့ transient field တွေကို skip လုပ်ပါတယ်။ `@Expose` ကတော့ ပိုတိကျစွာ ရွေးချယ်ချင်ရင်သုံးနိုင်ပြီး၊ ဒါကိုသုံးမယ်ဆိုရင် `Gson gson = new GsonBuilder().excludeFieldsWithoutExposeAnnotation().create();` လို့ ထပ်ပြောပေးရပါတယ် (မဟုတ်ရင် annotation ကို Gson က ignore လုပ်ပါလိမ့်မယ်).

### ၆။ QRCode Project အတွက် လက်တွေ့ဥပမာ

Weather API integration part မှာ လေ့လာခဲ့တဲ့ REST API response ကို ပြန်ပြောင်ရင်:

```java
public class WeatherResponse {
    @SerializedName("temp_c")
    private double temperatureCelsius;

    @SerializedName("weather_desc")
    private String description;

    @SerializedName("city_name")
    private String city;
}
```

API ကနေ `{"temp_c": 32.5, "weather_desc": "Sunny", "city_name": "Yangon"}` ဆိုတဲ့ JSON ပြန်လာရင် `@SerializedName` က field name (Java convention) နဲ့ API key name (API provider သတ်မှတ်ထားတဲ့ format) ကြားက gap ကို ချိတ်ဆက်ပေးတာပါ — Java code ဘက်မှာ camelCase convention ကို ဆက်ထိန်းထားနိုင်ပြီး API ဘက်က format ကိုလည်း အတိအကျ လိုက်နာနိုင်ပါတယ်။
