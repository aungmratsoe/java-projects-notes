gRPC မှာ token/auth ကို REST နဲ့ ဘယ်လိုကွာခြားစွာ handle လုပ်လဲ ရှင်းပြပါမယ်။

## အဓိက ကွာခြားချက်

REST မှာ token ကို **HTTP Header** ထဲထည့်ပို့တယ်။ gRPC မှာလည်း concept တူတူပါပဲ — ဒါပေမဲ့ "Header" မဟုတ်ဘဲ **Metadata** လို့ခေါ်ပြီး၊ request တစ်ခုချင်းစီမှာ manual ထည့်စရာမလိုဘဲ **Interceptor** ဆိုတဲ့ mechanism နဲ့ **အလိုအလျောက်** ထည့်ပေးနိုင်တယ်။

|**အချက်အလက်**|**REST**|**gRPC**|
|---|---|---|
|**Token ထည့်နေရာ**|HTTP Header|Metadata|
|**Auto-attach နည်းလမ်း**|Manual (request တိုင်း code ရေးရ)|Interceptor (တစ်ခါသတ်မှတ်ရုံ)|
|**Protocol**|HTTP/1.1 (JSON)|HTTP/2 (Binary/Protobuf)|

## Implementation (Java gRPC Client)

### 1️⃣ CallCredentials — Token ကို metadata ထဲ ထည့်ဖို့

```java
import io.grpc.*;
import java.util.concurrent.Executor;

public class TokenCallCredentials extends CallCredentials {
    private static final Metadata.Key<String> AUTH_KEY = 
        Metadata.Key.of("authorization", Metadata.ASCII_STRING_MARSHALLER);
    
    @Override
    public void applyRequestMetadata(RequestInfo requestInfo, Executor appExecutor,
                                       MetadataApplier applier) {
        appExecutor.execute(() -> {
            try {
                // TokenManager ကနေ valid token ကို ယူမယ် (expire ဖြစ်ရင် auto-refresh)
                String token = TokenManager.getValidAccessToken();
                
                Metadata metadata = new Metadata();
                metadata.put(AUTH_KEY, "Bearer " + token);
                applier.apply(metadata);
            } catch (Exception e) {
                applier.fail(Status.UNAUTHENTICATED.withCause(e));
            }
        });
    }
    
    @Override
    public void thisUsesUnstableApi() {}
}
```

### 2️⃣ Client Interceptor — Request တိုင်းအတွက် auto attach (ရွေးချယ်နိုင်တဲ့ နည်းလမ်း)

```java
import io.grpc.*;

public class AuthInterceptor implements ClientInterceptor {
    private static final Metadata.Key<String> AUTH_KEY = 
        Metadata.Key.of("authorization", Metadata.ASCII_STRING_MARSHALLER);
    
    @Override
    public <ReqT, RespT> ClientCall<ReqT, RespT> interceptCall(
            MethodDescriptor<ReqT, RespT> method, CallOptions callOptions, Channel next) {
        
        return new ForwardingClientCall.SimpleForwardingClientCall<ReqT, RespT>(
                next.newCall(method, callOptions)) {
            @Override
            public void start(Listener<RespT> responseListener, Metadata headers) {
                try {
                    String token = TokenManager.getValidAccessToken();
                    headers.put(AUTH_KEY, "Bearer " + token);
                } catch (Exception e) {
                    throw new RuntimeException("Token ရယူလို့မရပါ", e);
                }
                super.start(responseListener, headers);
            }
        };
    }
}
```

### 3️⃣ Channel Setup — Interceptor/Credentials ကို channel မှာ တွဲသုံးခြင်း

```java
import io.grpc.*;

public class GrpcClientSetup {
    
    public static ManagedChannel createChannel() {
        return ManagedChannelBuilder.forAddress("api.example.com", 443)
                .useTransportSecurity() // TLS/SSL - gRPC မှာ default အားဖြင့် encrypted connection
                .intercept(new AuthInterceptor()) // token auto-attach
                .build();
    }
    
    public static void main(String[] args) throws Exception {
        // ပထမဆုံး login
        TokenManager.login("username", "password");
        
        ManagedChannel channel = createChannel();
        
        // Stub ဖန်တီးတယ် - request ခေါ်တိုင်း Interceptor က token ကို auto ထည့်ပေးမယ်
        MyServiceGrpc.MyServiceBlockingStub stub = MyServiceGrpc.newBlockingStub(channel);
        
        MyResponse response = stub.someMethod(MyRequest.newBuilder().build());
        System.out.println(response);
    }
}
```

### 4️⃣ Server-side (401-တန်ဖိုးထူးခြားချက်) — token invalid ဖြစ်ရင် error handling

```java
// gRPC မှာ HTTP 401 မရှိဘူး - Status code သုံးတယ်
try {
    MyResponse response = stub.someMethod(request);
} catch (StatusRuntimeException e) {
    if (e.getStatus().getCode() == Status.Code.UNAUTHENTICATED) {
        // Token expired/invalid ဖြစ်နေတယ် - refresh (သို့) login ပြန်လုပ်ပါ
        System.out.println("Authentication failed: " + e.getMessage());
    }
}
```

## Streaming API မှာ ထူးခြားချက်

gRPC ရဲ့ special feature က **Streaming** (server/client/bidirectional) ပါ — token ကို stream တစ်ခုလုံးအတွက် **connection စတင်တဲ့ အချိန်တစ်ခါတည်း** ထည့်ရုံပါပဲ (REST မှာဆို request တစ်ခုချင်းစီအတွက် ပြန်ထည့်ရမယ်)။ ဒါပေမဲ့ stream ကြာကြာဆက်ထားရင် token expire ဖြစ်နိုင်လို့ **long-lived stream** တွေအတွက် token refresh logic ကို ပိုသေချာ စဉ်းစားရတယ်။

## Summary

|Concept|REST|gRPC|
|---|---|---|
|Token ထားနေရာ|`Authorization` header|`authorization` metadata key|
|Auto-attach|manual code (request တိုင်း)|Interceptor/CallCredentials (တစ်ခါသတ်မှတ်)|
|Unauthorized error|HTTP 401|`Status.UNAUTHENTICATED`|
|Encryption|HTTPS ဖြစ်ဖို့ configure လိုတယ်|`useTransportSecurity()` က default|

---

Server-streaming/Bidirectional streaming မှာ token refresh ကို ဘယ်လို handle လုပ်ရမလဲ ပိုအသေးစိတ် ကြည့်ချင်ရင် ပြောပါ။
