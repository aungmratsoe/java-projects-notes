# PART 2

# Why Redis Cache?

Problem:

Example:

Cafe Menu:

```text
500 Products

```

Customers:

```text
50,000 requests/day

```

Without Cache:

```text
50,000

↓

MySQL Queries

```

Database load မြင့်မယ်။

---

With Redis:

```text
First Request


Client

 |

Redis

 |

Miss

 |

MySQL

 |

Save Redis


```

Next:

```text
Client

 |

Redis

 |

Fast Response

```

# PART 6

# Cache Product List

Before:

```java
public List<ProductResponse> findAll(){

return repository.findAll();

}

```

---

After:

```java
@Cacheable(
value="products"
)

public List<ProductResponse> findAll(){


return repository.findAll()

.stream()

.map(this::map)

.toList();


}

```

---

Meaning:

```text
First Call:

API

↓

Redis Empty

↓

MySQL

↓

Save Redis



Second Call:

API

↓

Redis

↓

Return

```

# PART 15

# Kafka Producer Service

Create:

```text
event/ProductEventPublisher.java

```

Code:

```java
@Service

@RequiredArgsConstructor

public class ProductEventPublisher {



private final KafkaTemplate<String,Object>

kafkaTemplate;



public void publish(
ProductCreatedEvent event
){


kafkaTemplate.send(

"product.created",

event.productId().toString(),

event

);


}


}

```

---

# PART 16

# Publish Event After Create

ProductService:

Before:

```java

```

---

After:

```java
Product saved =
repository.save(product);



publisher.publish(

new ProductCreatedEvent(

saved.getId(),

saved.getName(),

saved.getPrice(),

saved.getCategory().getId()

)

);

```
