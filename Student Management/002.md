**Database Schema — အသေးစိတ်ရှင်းလင်းချက်**

ဒီ ER Diagram ထဲမှာ table ၈ ခုကို relationship တွေနဲ့ ပြထားပါတယ်။ Table တစ်ခုချင်းစီရဲ့ အခန်းကဏ္ဍကို ရှင်းပြပါမယ် —

**Core Tables**

- **classes** — အတန်းတစ်ခုစီ (Grade 10-A စသည်) ကို ကိုယ်စားပြု၊ `teacher_id` ဖြင့် တာဝန်ခံဆရာနှင့် ချိတ်ဆက်
- **students** — student record အဓိက table၊ `class_id` FK ဖြင့် classes table နဲ့ ချိတ်ဆက် (1 class : many students)
- **teachers** — ဆရာ/ဆရာမ record၊ `user_id` FK ဖြင့် login account နှင့် ချိတ်ဆက်နိုင် (optional)
- **subjects** — အတန်းတစ်ခုစီအောက်က ဘာသာရပ်များ

**Transaction/Activity Tables** (students ကို FK ဖြင့် ကိုးကား)

- **attendance** — student တစ်ဦးချင်းစီရဲ့ နေ့စဉ်တက်ရောက်မှု (Present/Absent/Leave), `(student_id, date)` ကို UNIQUE ထားထားလို့ တစ်ရက်ကို record တစ်ခုသာ ဝင်နိုင်
- **fees** — ကျသင့်ငွေ vs ပေးဆောင်ပြီးငွေ tracking, `status` (Paid/Pending/Partial) ဖြင့် ချက်ချင်းစစ်နိုင်
- **exams** — subject တစ်ခုချင်းစီအတွက် marks/grade, `student_id` + `subject_id` နှစ်ခုစလုံးကို FK ချိတ်

**Auth Table**

- **users** — login accounts (Admin/Teacher/Staff role-based access အတွက်)

**Relationship key points**

- `classes` 1 → many `students`, `subjects`
- `students` 1 → many `attendance`, `fees`, `exams`
- Cascade delete: student တစ်ဦး ဖျက်လိုက်ရင် attendance/fees/exams records တွေပါ auto-ဖျက်သွားအောင် `ON DELETE CASCADE` သုံးထားပါတယ် (ဒါပေမယ့် class ဖျက်လိုက်ရင် students တွေကတော့ `class_id = NULL` ဖြစ်ရုံပဲ ဆက်ရှိနေပါမယ်)
