# SOAP API အသေးစိတ်

## SOAP ဆိုတာဘာလဲ

**SOAP (Simple Object Access Protocol)** ဆိုတာ Microsoft က 1998 ခုနှစ်လောက်မှာ တီထွင်ခဲ့တဲ့ **protocol** တစ်ခုဖြစ်ပါတယ်။ REST က architectural **style** (guideline) ဖြစ်ပေမယ့် SOAP က **strict protocol** ဖြစ်လို့ rule တွေ ပိုတင်းကျပ်ပါတယ်။ Message format အနေနဲ့ **XML** ကိုပဲ အသုံးပြုရပါတယ်။

## SOAP Message ရဲ့ Structure

SOAP request/response တိုင်းဟာ **XML envelope** ပုံစံနဲ့ ဖြစ်ရပါတယ်:

```xml
<?xml version="1.0"?>
<soap:Envelope xmlns:soap="http://www.w3.org/2003/05/soap-envelope">

  <soap:Header>
    <!-- Authentication, transaction info စသည် (optional) -->
  </soap:Header>

  <soap:Body>
    <!-- Actual request/response data -->
    <GetUserRequest>
      <UserId>123</UserId>
    </GetUserRequest>
  </soap:Body>

</soap:Envelope>
```

|Element|Purpose|
|---|---|
|**Envelope**|SOAP message တစ်ခုလုံးရဲ့ root container|
|**Header**|Authentication, session info, transaction data (optional)|
|**Body**|Actual request/response content (required)|
|**Fault**|Error ဖြစ်ရင် Body ထဲမှာ error detail ပါဝင်တဲ့ element|

## WSDL (Web Services Description Language)

SOAP API တိုင်းမှာ **WSDL file** ဆိုတာ ပါဝင်ပါတယ် — API ရဲ့ "contract" (blueprint) လိုမျိုးပါ။

- ဘယ် operation (method) တွေ ရနိုင်လဲ
- Input/output parameter structure ဘာတွေလဲ
- Data type ဘာတွေလဲ

ဒါတွေကို WSDL file (`.wsdl`) ထဲမှာ **အကုန်ကြိုသတ်မှတ်ထားရ**ပါတယ်။ ဒါကြောင့် client tool တွေက WSDL ကို ဖတ်ပြီး code auto-generate လုပ်နိုင်ပါတယ် (**strongly typed**)။

## REST vs SOAP — ကွာခြားချက်

||REST|SOAP|
|---|---|---|
|Type|Architectural style|Protocol|
|Data format|JSON, XML, plain text|XML ချည်းသာ|
|Transport|HTTP ချည်းသာ|HTTP, SMTP, TCP စသည် အများကြီး|
|Message size|သေးငယ်|ကြီးမား (XML envelope overhead)|
|Speed|မြန်|ပိုနှေး|
|Contract|Optional (OpenAPI/Swagger)|Required (WSDL) — strict|
|Security|HTTPS + custom auth|**WS-Security** (built-in standard)|
|Transaction support|Manual handle ရ|**ACID transaction** built-in support|
|Error handling|HTTP status code|SOAP Fault element|
|Use case|Web/mobile app, public API|Banking, enterprise, legacy system|

## SOAP ဘာကြောင့် ဒီနေ့တိုင် သုံးနေသေးလဲ

REST က developer-friendly ပြီး popular ဖြစ်နေပေမယ့် SOAP ကို အောက်ပါ scenario တွေမှာ ဆက်သုံးနေကြပါတယ်:

1. **Banking / Financial systems** — WS-Security standard, transaction reliability (ACID) လိုအပ်လို့
2. **Legacy enterprise systems** — old system တွေ SOAP နဲ့ ရေးထားပြီးသားဖြစ်လို့ migrate မလုပ်ချင်ကြ
3. **Formal contract လိုအပ်တဲ့ B2B integration** — WSDL က strict schema validation ပေးလို့
4. **Government / Healthcare** — compliance requirement တင်းကျပ်တဲ့နေရာများ

## Java မှာ SOAP Client ခေါ်ခြင်း

Java မှာ SOAP web service ကို consume လုပ်ဖို့ **JAX-WS** (Jakarta XML Web Services) ကို standard အနေနဲ့ သုံးပါတယ်။

### Method — WSDL ကနေ Java class auto-generate (wsimport tool)

```bash
wsimport -keep -p com.example.soapclient http://example.com/service?wsdl
```

ဒီ command က WSDL ကို ဖတ်ပြီး Java class (stub) တွေ auto-generate လုပ်ပေးပါတယ်။ ပြီးရင်:

```java
import com.example.soapclient.UserService;
import com.example.soapclient.UserServicePort;

public class SoapClientDemo {
    public static void main(String[] args) {
        UserService service = new UserService();
        UserServicePort port = service.getUserServicePort();

        // ရိုးရိုး method ခေါ်သလိုပဲ — auto-generated stub ကနေတစ်ဆင့်
        User user = port.getUser(123);
        System.out.println("Name: " + user.getName());
    }
}
```

### Maven Dependency (JAX-WS runtime)

```xml
<dependency>
    <groupId>com.sun.xml.ws</groupId>
    <artifactId>jaxws-rt</artifactId>
    <version>4.0.2</version>
</dependency>
```

## Swing App မှာ SOAP Integration Pattern

REST/WebSocket နဲ့ concept တူတူပါပဲ — SOAP call ဟာလည်း time ကြာနိုင်တဲ့ operation ဖြစ်လို့ **SwingWorker** ထဲမှာပဲ လုပ်ရပါမယ်:

```java
public class SoapFetchWorker extends SwingWorker<User, Void> {
    private final int userId;

    public SoapFetchWorker(int userId) {
        this.userId = userId;
    }

    @Override
    protected User doInBackground() throws Exception {
        UserService service = new UserService();
        UserServicePort port = service.getUserServicePort();
        return port.getUser(userId); // auto-generated stub call
    }

    @Override
    protected void done() {
        try {
            User user = get();
            // UI update ဒီမှာ
        } catch (Exception e) {
            // error handling
        }
    }
}
```

## SOAP Fault Handling

SOAP မှာ error ဖြစ်ရင် HTTP status code (404, 500) အစား **SOAPFaultException** throw ဖြစ်ပါတယ်:

```java
try {
    User user = port.getUser(999);
} catch (SOAPFaultException e) {
    System.out.println("SOAP Fault: " + e.getFault().getFaultString());
}
```

SOAP request/response ကို raw XML level (WSDL auto-generate မသုံးဘဲ) ကနေ manually build ပြီး ခေါ်တဲ့ approach ကိုလည်း လေ့လာချင်ရင် ပြောပါ — `SOAPConnection` API သုံးပုံ ဆက်ရှင်းပြပေးနိုင်ပါတယ်။
