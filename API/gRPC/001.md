# gRPC (Google Remote Procedure Call) အသေးစိတ်

## gRPC ဆိုတာဘာလဲ

**gRPC** ဆိုတာ Google က 2015 ခုနှစ်လောက်မှာ open-source လုပ်ခဲ့တဲ့ **modern RPC framework** ဖြစ်ပါတယ်။ RPC (Remote Procedure Call) ရဲ့ concept က "remote server ပေါ်က function ကို local function ခေါ်သလိုပဲ ခေါ်လို့ရတယ်" ဆိုတာပါ။

gRPC ရဲ့ အဓိက အင်္ဂါရပ်နှစ်ခု:

- **HTTP/2** ပေါ်မှာ အခြေခံ (HTTP/1.1 ထက် performance ပိုကောင်း)
- **Protocol Buffers (protobuf)** ကို data serialization format အနေနဲ့ သုံး (JSON/XML ထက် binary format ဖြစ်လို့ size သေးပြီး speed မြန်)

## Protocol Buffers (protobuf) ဆိုတာဘာလဲ

Protobuf ဆိုတာ Google ရဲ့ **binary serialization format** တစ်ခုဖြစ်ပါတယ်။ JSON လို text-based မဟုတ်ဘဲ binary ဖြစ်လို့ human-readable မဟုတ်ပေမယ့် **size ပိုသေး၊ parse ပိုမြန်**ပါတယ်။

Service structure နဲ့ data structure ကို `.proto` file ထဲမှာ ကြိုသတ်မှတ်ရပါတယ်:

```protobuf
syntax = "proto3";

package userservice;

// Data structure သတ်မှတ်ချက်
message User {
  int32 id = 1;
  string name = 2;
  string email = 3;
}

message GetUserRequest {
  int32 id = 1;
}

// Service (available RPC methods) သတ်မှတ်ချက်
service UserService {
  rpc GetUser (GetUserRequest) returns (User);
}
```

`= 1`, `= 2` စတဲ့ number တွေက field position (binary encoding အတွက် index) ဖြစ်ပြီး field name ပြောင်းလည်း backward-compatible ဖြစ်နေအောင် သုံးထားတာပါ။

## gRPC ရဲ့ Communication Pattern ၄ မျိုး

### ၁။ Unary RPC (ပုံမှန် request-response)

Client တစ်ခု request ပို့၊ server တစ်ခု response ပြန် — REST လိုမျိုးပါပဲ

```protobuf
rpc GetUser (GetUserRequest) returns (User);
```

### ၂။ Server Streaming RPC

Client request တစ်ခုတည်းပို့ပေမယ့် server က response **stream** အများကြီး ပြန်ပို့

```protobuf
rpc ListUsers (ListUsersRequest) returns (stream User);
```

_ဥပမာ - user တစ်ထောင်စာရင်း ရယူချင်ရင် တစ်ခါတည်း အကုန်မပို့ဘဲ တစ်ယောက်ချင်း stream ပို့_

### ၃။ Client Streaming RPC

Client က data **stream** ပို့ပြီး server က response တစ်ခုတည်း ပြန်ပို့

```protobuf
rpc UploadUsers (stream User) returns (UploadSummary);
```

_ဥပမာ - file upload လုပ်တုန်း chunk အလိုက် stream ပို့ပြီး ပြီးမှ summary ပြန်ရ_

### ၄။ Bidirectional Streaming RPC

Client နဲ့ server နှစ်ဖက်စလုံး stream ချင်း တစ်ပြိုင်နက် ဆက်သွယ်

```protobuf
rpc Chat (stream ChatMessage) returns (stream ChatMessage);
```

_ဥပမာ - real-time chat, live collaboration_

## Code Generation Flow

gRPC ရဲ့ workflow က WSDL/wsimport concept နဲ့ ဆင်တူပါတယ် — `.proto` file ကနေ Java class auto-generate လုပ်ပါတယ်:

```
.proto file → protoc compiler → Java client/server stub classes (auto-generated)
```

`mvn compile` run လိုက်ရင် `.proto` file ထဲက definition ကနေ Java stub class တွေ auto-generate ဖြစ်ပါလိမ့်မယ်။

## Server Side (Java) ဥပမာ

```java
import io.grpc.Server;
import io.grpc.ServerBuilder;
import io.grpc.stub.StreamObserver;

public class UserServiceImpl extends UserServiceGrpc.UserServiceImplBase {

    @Override
    public void getUser(GetUserRequest request, StreamObserver<User> responseObserver) {
        // request.getId() ကနေ actual data ရှာယူ
        User user = User.newBuilder()
                .setId(request.getId())
                .setName("Aung Aung")
                .setEmail("aungaung@example.com")
                .build();

        responseObserver.onNext(user);   // response ပို့
        responseObserver.onCompleted();  // stream ပြီးကြောင်း အသိပေး
    }
}

public class GrpcServer {
    public static void main(String[] args) throws Exception {
        Server server = ServerBuilder.forPort(9090)
                .addService(new UserServiceImpl())
                .build();

        server.start();
        System.out.println("gRPC server started on port 9090");
        server.awaitTermination();
    }
}
```

## Client Side (Swing App) ဥပမာ

```java
import io.grpc.ManagedChannel;
import io.grpc.ManagedChannelBuilder;

public class GrpcClient {

    public static User fetchUser(int userId) {
        ManagedChannel channel = ManagedChannelBuilder
                .forAddress("localhost", 9090)
                .usePlaintext() // TLS မသုံးဘဲ testing/local အတွက် (production မှာ TLS သုံးသင့်)
                .build();

        try {
            UserServiceGrpc.UserServiceBlockingStub stub =
                    UserServiceGrpc.newBlockingStub(channel);

            GetUserRequest request = GetUserRequest.newBuilder()
                    .setId(userId)
                    .build();

            return stub.getUser(request); // synchronous call — blocking stub
        } finally {
            channel.shutdown();
        }
    }
}
```

## SwingWorker ထဲ ချိတ်ဆက်ခြင်း

```java
public class GrpcUserWorker extends SwingWorker<User, Void> {
    private final int userId;

    public GrpcUserWorker(int userId) {
        this.userId = userId;
    }

    @Override
    protected User doInBackground() throws Exception {
        return GrpcClient.fetchUser(userId); // gRPC blocking call ဒီမှာ
    }

    @Override
    protected void done() {
        try {
            User user = get();
            // UI update — user.getName(), user.getEmail() စသည်
        } catch (Exception e) {
            // error handling
        }
    }
}
```

> **Blocking stub** ကို `doInBackground()` ထဲမှာပဲ ခေါ်ရပါမယ် — EDT ပေါ်မှာ တိုက်ရိုက်ခေါ်ရင် UI freeze ဖြစ်ပါလိမ့်မယ်။

## gRPC vs REST vs GraphQL vs WebSocket — Final Comparison

||REST|GraphQL|WebSocket|gRPC|
|---|---|---|---|---|
|Data format|JSON|JSON|Text/Binary any|Protobuf (binary)|
|Protocol|HTTP/1.1|HTTP/1.1|TCP (ws/wss)|HTTP/2|
|Browser support|Direct|Direct|Direct|မရ (gRPC-Web လိုအပ်)|
|Streaming|မရ|Subscription (WS-based)|Native bidirectional|4 modes built-in|
|Type safety|Weak|Strong (schema)|မရှိ|Strong (protobuf)|
|Speed|အလယ်အလတ်|အလယ်အလတ်|မြန်|အမြန်ဆုံး|
|Best for|Public/web API|Flexible client query|Real-time client-facing|Microservices internal|

## gRPC ရဲ့ Limitation (သိထားသင့်တာ)

1. **Browser directly မသုံးနိုင်** — web frontend က gRPC-Web proxy (Envoy) လိုအပ်ပါတယ်။ Java Swing desktop app ကတော့ ပြဿနာမရှိပါ (native gRPC client သုံးလို့ရ)
2. **Human-readable မဟုတ်** — debug လုပ်ရတာ REST/JSON ထက် ခက်တယ် (binary format ကြောင့်)
3. **Learning curve** — protobuf syntax, code generation setup လိုအပ်လို့ REST ထက် setup ပိုများ

ဒီအထိနဲ့ API type ငါးမျိုးလုံး (REST, SOAP, GraphQL, WebSocket, gRPC) ကို Java/Swing integration ဥပမာနဲ့တကွ ပြီးပါပြီ။ အားလုံးကို **summary/comparison table** တစ်ခုတည်းနဲ့ ပြန်လည်သုံးသပ်ချင်ပါသလား၊ ဒါမှမဟုတ် Swing project အတွင်းမှာ ဘယ် API type ကို ဘယ်လို scenario အတွက် ရွေးသင့်လဲဆိုတာ decision guide တစ်ခု ပြုစုပေးရမလား။
