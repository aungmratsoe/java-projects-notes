# REST API အသေးစိတ်

## REST ဆိုတာဘာလဲ

**REST (Representational State Transfer)** ဆိုတာ Roy Fielding ဆိုတဲ့ scientist က 2000 ခုနှစ်မှာ သူ့ PhD dissertation မှာ ပထမဆုံး ဖော်ပြခဲ့တဲ့ **architectural style** တစ်ခုဖြစ်ပါတယ်။ Protocol တစ်ခုမဟုတ်ဘဲ "ဒီအတိုင်း design လုပ်ရင် system က scalable, maintainable ဖြစ်မယ်" ဆိုတဲ့ **guideline/principle** အစုအဝေးပါ။

## REST ရဲ့ အခြေခံသဘောတရား ၆ ချက် (Constraints)

### ၁။ Client-Server

- Client (UI) နဲ့ Server (data/logic) ကို သီးခြားစီ ခွဲထားပါတယ်
- Client က UI ကိုပဲ တာဝန်ယူ၊ Server က data storage/business logic ကို တာဝန်ယူ

### ၂။ Stateless

- Request တစ်ခုချင်းစီဟာ **ကိုယ်ပိုင်လုံလောက်တဲ့ information** ပါဝင်ရပါတယ်
- Server ဘက်က client ရဲ့ previous request ကို ဘာမှ မမှတ်ထားပါ
- Authentication token လိုအပ်ရင် request တိုင်းမှာ ထည့်ပို့ရပါတယ် (session state မသိမ်းထား)

### ၃။ Cacheable

- Response တွေကို cache လုပ်ထားနိုင်ရပါတယ် (performance အတွက်)
- Response header မှာ cacheable ဟုတ်/မဟုတ် ဖော်ပြထားရပါတယ်

### ၄။ Uniform Interface

- URL structure, HTTP methods တွေကို consistent ဖြစ်အောင် သုံးရပါတယ် (အောက်မှာ အသေးစိတ်ရှင်းမယ်)

### ၅။ Layered System

- Client က server ကို တိုက်ရိုက်ဆက်သွယ်နေသလား၊ load balancer/proxy ကြားက ဖြတ်နေသလား သိစရာမလိုပါ

### ၆။ Code on Demand (optional)

- Server က client ဆီကို executable code (JavaScript) ပို့နိုင်ပါတယ် (မလိုအပ်ရင် skip လို့ရ)

## HTTP Methods (CRUD operations)

|HTTP Method|Operation|ဥပမာ|
|---|---|---|
|**GET**|Data ဖတ်ခြင်း (Read)|`GET /users` — user list အားလုံးရယူ|
|**POST**|Data အသစ်ဖန်တီးခြင်း (Create)|`POST /users` — user အသစ်ထည့်|
|**PUT**|Data အားလုံး ပြင်ခြင်း (Update/Replace)|`PUT /users/123` — user 123 ကို အကုန်ပြောင်း|
|**PATCH**|Data တစ်စိတ်တစ်ပိုင်း ပြင်ခြင်း (Partial Update)|`PATCH /users/123` — field တစ်ခုပဲ ပြောင်း|
|**DELETE**|Data ဖျက်ခြင်း|`DELETE /users/123` — user 123 ဖျက်|

## Resource-Based URL Design

REST မှာ URL က **resource (noun)** ကို ကိုယ်စားပြုရပါတယ် — action (verb) မဖြစ်စေရပါ:

✅ **ကောင်းတဲ့ design:**

```
GET    /users          → user list ရယူ
GET    /users/123      → user id 123 ရယူ
POST   /users          → user အသစ်ဖန်တီး
PUT    /users/123      → user 123 update
DELETE /users/123      → user 123 ဖျက်
GET    /users/123/orders → user 123 ရဲ့ order များ
```

❌ **မကောင်းတဲ့ design (verb သုံးထားတာ):**

```
GET /getAllUsers
POST /createNewUser
POST /deleteUser?id=123
```

## HTTP Status Codes (Response)

|Code|အဓိပ္ပာယ်|
|---|---|
|**200 OK**|အောင်မြင်စွာ ပြီးစီး|
|**201 Created**|Resource အသစ် ဖန်တီးအောင်မြင်|
|**204 No Content**|အောင်မြင်ပေမယ့် response body မရှိ (ဥပမာ DELETE)|
|**400 Bad Request**|Client ဘက်က request ပုံစံမှား|
|**401 Unauthorized**|Authentication လိုအပ်|
|**403 Forbidden**|Permission မရှိ|
|**404 Not Found**|Resource မတွေ့|
|**500 Internal Server Error**|Server ဘက် error|

## Request/Response ဥပမာ (JSON)

**Request:**

```
POST /users HTTP/1.1
Content-Type: application/json

{
  "name": "Aung Aung",
  "email": "aungaung@example.com"
}
```

**Response:**

```
HTTP/1.1 201 Created
Content-Type: application/json

{
  "id": 123,
  "name": "Aung Aung",
  "email": "aungaung@example.com",
  "createdAt": "2026-08-02T10:00:00Z"
}
```

## Java Swing Project ကနေ REST API ခေါ်ချင်ရင်

### Method ၁: Java 11+ built-in HttpClient (library ထပ်ထည့်စရာမလို)

```java
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.net.URI;

HttpClient client = HttpClient.newHttpClient();
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/users"))
    .GET()
    .build();

HttpResponse<String> response = client.send(request, 
    HttpResponse.BodyHandlers.ofString());
System.out.println(response.body());
```

### Method ၂: OkHttp library (Maven dependency ထည့်ရ)

```xml
<dependency>
    <groupId>com.squareup.okhttp3</groupId>
    <artifactId>okhttp</artifactId>
    <version>4.12.0</version>
</dependency>
```

### JSON parse လုပ်ဖို့ Jackson library

```xml
<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
    <version>2.17.0</version>
</dependency>
```

Swing GUI (JTable, JList) ထဲမှာ REST API ကနေ ရလာတဲ့ data ကို ပြချင်ရင် — API call ကို **background thread (SwingWorker)** နဲ့ လုပ်ဖို့ လိုအပ်ပါတယ်၊ ဒါမှ UI freeze မဖြစ်ပါဘူး။
