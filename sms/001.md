ပေးထားသော Database Schema (MySQL dump) ဖိုင်များအရ ဇယား (Tables) များ၏ အချင်းချင်း ဆက်စပ်မှု (Relations / Foreign Key Relationships) များကို မြန်မာလို အောက်ပါအတိုင်း ရှင်းပြပေးလိုက်ပါတယ် -

  

### ၁။ `users` (အသုံးပြုသူများ) နှင့် `roles` (ရာထူး/အခွင့်အရေးအမျိုးအစားများ)

- **ဆက်စပ်ပုံ:** `users` ဇယားရှိ `role_id` သည် `roles` ဇယားရှိ `id` ကို ကိုးကားထားပါသည်။
    
      
    
- **ဆက်နွှယ်မှု:** တစ်ဦးချင်းစီသော **အသုံးပြုသူ (`users`) တစ်ဦးစီသည် `roles` ဇယားမှ ရာထူးတစ်ခုခု (Role) ကို သတ်မှတ်ခံထားရပါသည်**။ (Many-to-One ဆက်စပ်မှုရှိပြီး ရာထူးတစ်ခုကို အသုံးပြုသူ များစွာက ပိုင်ဆိုင်နိုင်ပါသည်)။
    
      
    

### ၂။ `audit_logs` (စစ်ဆေးရေးမှတ်တမ်းများ) နှင့် `users` (အသုံးပြုသူများ)

- **ဆက်စပ်ပုံ:** `audit_logs` ဇယားရှိ `user_id` သည် `users` ဇယားရှိ `id` ကို ကိုးကားထားပါသည်။
    
      
    
- **ဆက်နွှယ်မှု:** စနစ်အတွင်း လုပ်ဆောင်ချက်များကို မှတ်တမ်းတင်ထားသော **`audit_logs` တစ်ခုချင်းစီသည် မည်သည့်အသုံးပြုသူ (`users`) ကြောင့် ဖြစ်ပေါ်လာသည်ကို** ဆက်စပ်ဖော်ပြပေးသည်။ အသုံးပြုသူတစ်ဦး ဖျက်သိမ်းခံရပါက ဤ `user_id` ကို `NULL` အဖြစ်သို့ ပြောင်းလဲသွားစေရန် (`ON DELETE SET NULL`) ပြုလုပ်ထားပါသည်။
    
      
    

### ၃။ `role_permissions` (ရာထူးနှင့် လုပ်ပိုင်ခွင့်များ ချိတ်ဆက်ခြင်း)

ဤဇယားသည် `roles` နှင့် `permissions` ကြားတွင် **Many-to-Many (အပြန်အလှန် များပြားသော)** ဆက်စပ်မှုကို ဖန်တီးပေးရန်အတွက် ကြားခံအဖြစ် အသုံးပြုထားသော ဇယား (Junction Table) ဖြစ်ပါသည်။

  

- **ရာထူးနှင့် ချိတ်ဆက်မှု:** `role_permissions` ရှိ `role_id` သည် `roles` ဇယား၏ `id` ကို ကိုးကားထားသည်။
    
      
    
- **လုပ်ပိုင်ခွင့်နှင့် ချိတ်ဆက်မှု:** `role_permissions` ရှိ `permission_id` သည် `permissions` (လုပ်ပိုင်ခွင့်များ) ဇယား၏ `id` ကို ကိုးကားထားသည်။
    
      
    
- **ဆက်နွှယ်မှု:** **ရာထူးတစ်ခု (`roles`) တွင် လုပ်ပိုင်ခွင့်အမျိုးမျိုး (`permissions`) များစွာ ပါဝင်နိုင်ပြီး**၊ လုပ်ပိုင်ခွင့်တစ်ခုတည်းကိုလည်း ရာထူးအမျိုးမျိုးတွင် ပြန်လည်အသုံးပြုနိုင်ရန် ဤဇယားက ချိတ်ဆက်ပေးထားပါသည်။
