## အဖြေ — Lesson 7 ရဲ့ Quiz

`revalidate()` နဲ့ `repaint()` ကို ဖြုတ်ရင် — **Add Row နှိပ်လိုက်တိုင်း component ကတော့ panel ထဲ တကယ်ထည့်ပြီးသားပါ** (data structure အနေနဲ့ တော့ ရှိနေတယ်)၊ ဒါပေမဲ့ **screen ပေါ်မှာ မြင်ရမှာ မဟုတ်ပါဘူး** (သို့) **layout position အမှန် တွက်ပေးမှာ မဟုတ်ပါဘူး**။

အကြောင်းက Swing ဟာ performance အတွက် **automatic redraw မလုပ်ပါဘူး** — component ထည့်ပြီးတိုင်း "ငါ ပြောင်းလိုက်ပြီ၊ layout ပြန်တွက်ပေးပါ" (`revalidate`) နဲ့ "screen ကို ပြန်ဆွဲပေးပါ" (`repaint`) ကို **ကိုယ်တိုင်ခေါ်** ပေးဖို့ လိုပါတယ်။ `pack()` ကတော့ window size ကိုပါ auto ချိန်ပေးချင်ရင် ထပ်ခေါ်ရပါတယ်.

## သင်ခန်းစာ ၈ — Component List ကို Array/List နဲ့ Track လုပ်ခြင်း (Best Practice)

Lesson 7 မှာ `getComponentCount()` နဲ့ index ကိုင်တွယ်တာ error ဖြစ်လွယ်ပါတယ်။ Production code မှာတော့ component တွေကို **List** ထဲမှာ သိမ်းပြီး track လုပ်တာက ပိုကောင်းပါတယ်:

```java
import net.miginfocom.swing.MigLayout;
import javax.swing.*;
import java.util.ArrayList;
import java.util.List;

public class Lesson8 extends JFrame {

    private JPanel formPanel;
    private List<JLabel> labels = new ArrayList<>();
    private List<JTextField> fields = new ArrayList<>();
    private int rowCount = 0;

    public Lesson8() {
        setLayout(new MigLayout("wrap 1, fillx", "[grow,fill]"));

        formPanel = new JPanel(new MigLayout("wrap 2", "[right][grow,fill]"));
        add(formPanel, "growx");

        JButton addButton = new JButton("+ Add");
        addButton.addActionListener(e -> addRow());

        JButton removeButton = new JButton("− Remove");
        removeButton.addActionListener(e -> removeRow());

        JPanel controlPanel = new JPanel();
        controlPanel.add(addButton);
        controlPanel.add(removeButton);
        add(controlPanel, "align center");

        pack();
        setSize(400, 300);
        setLocationRelativeTo(null);
        setDefaultCloseOperation(EXIT_ON_CLOSE);
    }

    private void addRow() {
        rowCount++;
        JLabel label = new JLabel("Item " + rowCount + ":");
        JTextField field = new JTextField();

        labels.add(label);
        fields.add(field);

        formPanel.add(label);
        formPanel.add(field);

        formPanel.revalidate();
        formPanel.repaint();
        pack();
    }

    private void removeRow() {
        if (labels.isEmpty()) return;  // list အလွတ်ဆိုရင် ဘာမှမဖျက်

        // List ရဲ့ နောက်ဆုံး item ကို ထုတ်
        JLabel lastLabel = labels.remove(labels.size() - 1);
        JTextField lastField = fields.remove(fields.size() - 1);

        formPanel.remove(lastLabel);
        formPanel.remove(lastField);

        formPanel.revalidate();
        formPanel.repaint();
        pack();
    }

    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> new Lesson8().setVisible(true));
    }
}
```

### ဒီ Pattern ရဲ့ အားသာချက်:

- Index ကိုင်တွယ်စရာ မလို — `List.remove(size-1)` က ရိုးရိုးရှင်းရှင်း "နောက်ဆုံးအရာ ဖျက်" ပါ
- `labels.isEmpty()` check ထားလို့ **row 0 ခုကျန်တဲ့အချိန် Remove နှိပ်လို့ error တက်တာ** ကို ကာကွယ်ထားပါတယ်
- Field value တွေကို နောက်ပိုင်း refer ပြန်လုပ်ချင်ရင် (submit button ဆိုပါစို့) List ထဲကနေ တိုက်ရိုက် loop ပြီး ဖတ်လို့ရ

### 🤔 မေးခွန်း:

`removeRow()` method ထဲမှာ `if (labels.isEmpty()) return;` ဆိုတဲ့ check ကို ဖြုတ်ထားခဲ့ရင် — Remove button ကို row 0 ခု ကျန်စဉ် ဆက်နှိပ်ရင် ဘာဖြစ်နိုင်မလဲ (Java exception အနေနဲ့ ဘာမျိုး တက်နိုင်လဲ)?

## အဖြေ — Lesson 8 ရဲ့ Quiz

`if (labels.isEmpty()) return;` ကို ဖြုတ်ထားရင် — `labels.size() - 1` ဟာ `0 - 1 = -1` ဖြစ်သွားပြီး `labels.remove(-1)` ခေါ်လိုက်တာနဲ့ **`IndexOutOfBoundsException`** တက်ပါလိမ့်မယ်။

```
Exception in thread "AWT-EventQueue-0" java.lang.IndexOutOfBoundsException: 
Index -1 out of bounds for length 0
```

App က crash မဟုတ်ပေမယ့် (Swing event thread ထဲမှာ error ဖြစ်တာမို့ window ပိတ်မသွားပါ) — console မှာ stack trace ပေါ်ပြီး Remove button က အလုပ်မလုပ်တော့ပါဘူး။ ဒါကြောင့် **List/Array ကို ဖျက်/ဖတ်ခါနီးတိုင်း empty check ထားတာက အရေးကြီးတဲ့ defensive coding practice** ပါ။

## သင်ခန်းစာ ၉ — Debug Mode (Layout ပြဿနာ ရှာနည်း)

Layout မှန်မမှန် မသေချာရင် MigLayout ရဲ့ built-in debug feature ကို သုံးလို့ရပါတယ်:

```java
setLayout(new MigLayout("debug"));
```

Run ကြည့်ရင် component တစ်ခုချင်းစီ ပတ်ပတ်လည် **အနီရောင် grid line** တွေ auto ပေါ်ပြီး — cell boundary၊ column/row size ကို visual အနေနဲ့ တိုက်ရိုက်မြင်ရပါတယ်။ Layout ကျဉ်း/ကျယ်လွန်းတာ၊ component ဘယ်နေရာ ကျန်နေတာ ရှာဖို့ အလွန်အသုံးဝင်ပါတယ်.

### Lesson 8 code ထဲမှာ စမ်းကြည့်ပါ:

```java
setLayout(new MigLayout("debug, wrap 1, fillx", "[grow,fill]"));
```

Row/column boundary တွေ မြင်ရမှာပါ — production code မှာတော့ debug ဖျက်ထားရပါမယ်နော် (visual grid line က user ကို ပြသင့်တာ မဟုတ်ပါဘူး)။
