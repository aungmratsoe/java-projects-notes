Grok Ans

Student တစ်ယောက်ကို Admin က register လုပ်ပြီး QR ပါတဲ့ ID Card ထုတ်ပေး၊ Student က QR scan လုပ်ပြီး Account register လုပ်နိုင်တဲ့ system အတွက် အောက်ပါအတိုင်း စဉ်းစားနိုင်ပါတယ်။

### 1. ဘယ် Entity တွေလိုမလဲ?
အဓိက Entity များ:

- **User / Admin** – စနစ်ကို စီမံခန့်ခွဲသူ
- **Student** – ကျောင်းသား အချက်အလက် (name, student_id, class, email, phone စသည်)
- **IDCard** – ထုတ်ပေးထားသော ကတ် (card_number, issue_date, status)
- **QRCode** – QR data နှင့် metadata (token, expiry, used status)
- **Account** – ကျောင်းသား၏ login account (username/email, password_hash, status: pending/active)
- **RegistrationToken** (သို့မဟုတ် QR နှင့် ပေါင်းနိုင်) – one-time သို့မဟုတ် time-limited token
- **AuditLog** – ဘယ်သူက ဘာလုပ်ခဲ့လဲ မှတ်တမ်း

လိုအပ်သလို ထပ်ထည့်နိုင်သည်:
- Class / Department
- Role / Permission

### 2. ဘယ် Module တွေလိုမလဲ?
- **Admin Module** – Student create, ID Card generate, QR generate
- **Student Module** – Student profile management
- **QR Module** – QR generate, validate, mark as used
- **Auth / Account Module** – Account create, login, password reset
- **ID Card Module** – Card print/export (PDF/image)
- **Notification Module** (optional) – email/SMS အကြောင်းကြား
- **Audit / Logging Module**

### 3. ဘယ် Entity တွေ Relationship ရှိမလဲ?
- Admin **1 — N** Student (Admin တစ်ယောက်က Student အများကြီး create လုပ်နိုင်)
- Student **1 — 1** IDCard
- IDCard **1 — 1** QRCode (သို့မဟုတ် 1 — N ဖြစ်နိုင်သည်၊ reissue လုပ်ရင်)
- QRCode **1 — 1** RegistrationToken (သို့မဟုတ် QR ကိုယ်တိုင်က token ဖြစ်သည်)
- Student **1 — 1** Account (register ပြီးမှ ချိတ်ဆက်)
- Account **belongs to** Student

အဓိက flow မှာ:
Student → IDCard → QRCode → (scan) → Account

### 4. Flow ဘယ်လိုသွားမလဲ?
1. **Admin** သည် Student အချက်အလက် ထည့်သွင်းပြီး Create လုပ်သည်။
2. System က Student record ကို **Pending Registration** status ဖြင့် သိမ်းသည်။
3. System က unique, secure, time-limited **QR Token** တစ်ခု generate လုပ်သည်။
4. အဲဒီ Token ကို QR Code အဖြစ် ပြောင်းပြီး ID Card ပေါ်တွင် ထည့်သည် (PDF / Image ထုတ်ပေး)။
5. Admin သည် ID Card ကို Student ထံ ပေးသည်။
6. Student သည် QR ကို scan လုပ်သည် → Web/App က Token ကို ဖတ်သည်။
7. System က Token ကို validate လုပ်သည် (မသုံးရသေး၊ မကုန်သေး၊ မှန်ကန်မှု)။
8. မှန်ကန်ရင် Account registration form ကို ပြသည် (password သတ်မှတ်ရန်)။
9. Student က password ထည့်ပြီး Account ကို activate လုပ်သည်။
10. System က:
    - Account ကို Active လုပ်
    - QR / Token ကို Used အဖြစ် mark လုပ်
    - Student status ကို Registered အဖြစ် ပြောင်း

### 5. QR က ဘာတာဝန်ယူမလဲ?
- **One-time / limited-time invitation token** အဖြစ် ဆောင်ရွက်သည်။
- Student ကို မှန်ကန်စွာ ခွဲခြားပြီး Account ဖွင့်ခွင့်ပေးသည်။
- ကိုယ်တိုင် Account ဖွင့်ပေးခြင်း မဟုတ်ဘဲ၊ **secure registration link** အဖြစ်သာ တာဝန်ယူသည်။
- Token သည် student_id နှင့် ချိတ်ဆက်ထားရမည် (encrypted သို့မဟုတ် signed)။

### 6. Account က ဘာတာဝန်ယူမလဲ?
- Login / Authentication
- Authorization (ကျောင်းသား၏ ကိုယ်ပိုင် data ကို ကြည့်နိုင်ခွင့်)
- Password management
- Session management
- Profile update (နောက်ပိုင်း)

Account သည် Student record နှင့် 1:1 ချိတ်ဆက်ပြီးမှသာ အသုံးပြုနိုင်သည်။

### 7. Security ဘယ်နေရာမှာလိုမလဲ?
- **QR Token** သည်:
  - Cryptographically secure random
  - Short-lived (ဥပမာ 7–30 ရက်)
  - One-time use
  - Signed သို့မဟုတ် HMAC ဖြင့် protect
- Token ကို URL တွင် ထည့်သောအခါ HTTPS မဖြစ်မနေ
- QR scan ပြီး Account ဖွင့်သောအခါ rate limiting
- Password သည် strong policy + hashing (bcrypt/argon2)
- Admin actions အားလုံး audit log
- ID Card ပေါ်ရှိ QR သည် public ဖြစ်နိုင်သောကြောင့် token ကို မည်သူမဆို scan လုပ်နိုင်သည် → ထို့ကြောင့် token validation ကို တင်းကျပ်ရမည်
- Expired / already used token ကို ပြန်အသုံးမပြုနိုင်အောင်

### 8. Error ဖြစ်ရင် ဘာလုပ်မလဲ?
| အခြေအနေ | ကိုင်တွယ်ပုံ |
|---------|-------------|
| QR Token မရှိ / invalid | "Invalid or expired QR code" message + log |
| Token already used | "This QR has already been used" |
| Token expired | "QR code has expired. Please contact admin for a new one" |
| Student already has active account | "Account already exists" |
| Network / server error | User-friendly message + retry option |
| Admin က Student ကို ဖျက်ပြီးမှ QR scan လုပ် | "Student record not found" |
| Concurrent registration (တူညီသော token နှစ်ခု scan) | Database unique constraint + transaction ဖြင့် ကာကွယ် |

အရေးကြီးသော အချက်များ:
- Token ကို mark as used လုပ်သောအခါ atomic operation သုံးရမည်။
- Error message များတွင် sensitive information (student_id, internal error) မထည့်ရ။
- Admin အတွက် re-issue QR လုပ်နိုင်သော feature ထားရှိသင့်သည်။
