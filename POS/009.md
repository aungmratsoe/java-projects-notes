# Access Matrix (Role-Based Access Control) — Cafe POS အတွက်

Access Matrix ဆိုတာ "ဘယ် Role က ဘယ် Action/Resource ကို လုပ်ခွင့်ရှိလဲ" ဆိုတာကို systematic ဖြစ်အောင် define လုပ်တဲ့ concept ပါ။ `if role == ADMIN` စသည်ဖြင့် code ထဲမှာ scatter ဖြစ်နေမယ့်အစား, permission တွေကို တစ်နေရာတည်းမှာ centralize လုပ်ထားရင် maintain လုပ်ရ ပိုလွယ်တယ်။

## ၁. Access Matrix ဆိုတာ ဘာလဲ

|Action|ADMIN|MANAGER|CASHIER|
|---|---|---|---|
|Process Sale|✅|✅|✅|
|Void Transaction|✅|✅|❌|
|Apply Discount (>10%)|✅|✅|❌|
|Open/Close Shift|✅|✅|✅|
|View Own Shift Report|✅|✅|✅|
|View All Shifts Report|✅|✅|❌|
|Manage Menu Items|✅|✅|❌|
|Manage Users|✅|❌|❌|
|Refund|✅|✅|❌|
|Access Settings|✅|❌|❌|

ဒါက **design document** (row = action, column = role) ပါ — code ရေးခင်း ဒါကို အရင်ရေးထားတာက code implementation အချိန်မှာ ရှင်းလင်းစေတယ်။ Cafe POS သေးသေးလေးဆိုရင် Role ၃ ခုပဲရှိတတ်ပေမယ့် concept တူတူပါပဲ။

## ၂. Permission ကို Enum နဲ့ Model လုပ်ခြင်း

Boolean matrix ကို hard-code မလုပ်ဘဲ, `Permission` enum နဲ့ define လုပ်ပြီး role တစ်ခုစီကို permission set ချိတ်တာက scalable ဖြစ်တယ်:Ready — user တစ်ယောက်ရဲ့ role က permission set တစ်ခုကို ချိတ်ထားပြီး, action တစ်ခုလုပ်ခွင့်ရှိမရှိကို ဒီ permission set ကို reference လုပ်ပြီး စစ်တာပါ။

## ၃. Code Implementation

```java
public enum Permission {
    PROCESS_SALE,
    VOID_TRANSACTION,
    APPLY_DISCOUNT,
    MANAGE_MENU,
    MANAGE_USERS,
    VIEW_ALL_REPORTS,
    REFUND,
    ACCESS_SETTINGS
}

public class AccessMatrix {
    private static final Map<Role, Set<Permission>> MATRIX = new EnumMap<>(Role.class);
    
    static {
        MATRIX.put(Role.CASHIER, EnumSet.of(
            Permission.PROCESS_SALE
        ));
        
        MATRIX.put(Role.MANAGER, EnumSet.of(
            Permission.PROCESS_SALE,
            Permission.VOID_TRANSACTION,
            Permission.APPLY_DISCOUNT,
            Permission.MANAGE_MENU,
            Permission.VIEW_ALL_REPORTS,
            Permission.REFUND
        ));
        
        MATRIX.put(Role.ADMIN, EnumSet.allOf(Permission.class)); // အားလုံးရ
    }
    
    public static boolean hasPermission(Role role, Permission permission) {
        return MATRIX.getOrDefault(role, EnumSet.noneOf(Permission.class))
                      .contains(permission);
    }
}
```

`EnumSet` / `EnumMap` သုံးတာက performance ကောင်းတယ် (bitmask base) ၊ enum key တွေနဲ့ type-safe ဖြစ်တယ်။ Matrix table ကို static initializer block ထဲမှာ တစ်နေရာတည်းမှာ define ထားလို့ — permission ပြောင်းလိုချင်ရင် ဒီနေရာတစ်ခုပဲ ပြင်ရင်ရတယ်၊ code တစ်ခုလုံးကို ရှာစရာမလို။

## ၄. SessionManager ထဲမှာ သုံးပုံ

```java
public class SessionManager {
    // ... user, shift fields
    
    public boolean can(Permission permission) {
        if (currentUser == null) return false;
        return AccessMatrix.hasPermission(currentUser.getRole(), permission);
    }
}
```

UI layer မှာ button တွေကို enable/disable လုပ်ဖို့ ဒီလို သုံးလို့ရတယ်:

```java
btnVoid.setEnabled(SessionManager.getInstance().can(Permission.VOID_TRANSACTION));
btnDiscount.setEnabled(SessionManager.getInstance().can(Permission.APPLY_DISCOUNT));
```

**Important**: UI button disable လုပ်ရုံနဲ့ မလုံလောက်ပါ — button ကို enable ဖြစ်အောင် DevTools/hack လုပ်ခဲ့လို့ရနိုင်တာမို့, actual action (ဥပမာ - void sale) လုပ်တဲ့ backend/service method ထဲမှာလည်း permission check ထပ်ထည့်ရမယ်:

```java
public void voidTransaction(int saleId) {
    if (!SessionManager.getInstance().can(Permission.VOID_TRANSACTION)) {
        throw new SecurityException("Permission denied: VOID_TRANSACTION");
    }
    // actual void logic...
}
```

ဒါက **defense in depth** concept ပါ — UI layer မှာလည်း စစ်၊ business logic layer မှာလည်း စစ်။ Layer တစ်ခုတည်းကို မယုံပါနဲ့။

## ၅. Database ထဲ Permission ကို Store လုပ်ချင်ရင်

Matrix ကို code ထဲ hard-code မလုပ်ဘဲ database ထဲ store ချင်ရင် (admin က UI ကနေ permission ပြောင်းလို့ရအောင်):

```sql
CREATE TABLE role_permissions (
    role VARCHAR(20) NOT NULL,
    permission VARCHAR(50) NOT NULL,
    PRIMARY KEY (role, permission)
);
```

App startup မှာ ဒီ table ကနေ `Map<Role, Set<Permission>>` ကို load ထည့်ပြီး in-memory cache အနေနဲ့ သုံးလို့ရတယ် — sales POS လိုမျိုး app အတွက်တော့ code-based matrix ပဲ လုံလောက်ပြီး, admin-configurable permission လိုမှသာ database approach လိုမယ်။
