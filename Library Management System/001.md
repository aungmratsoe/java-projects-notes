
# Library Management System (LMS) — Java Swing Project လမ်းညွှန်

## ၁။ Business Idea ဘာလဲ

စာကြည့်တိုက်တစ်ခု (ကျောင်း၊ တက္ကသိုလ်၊ ရပ်ရွာ) ရဲ့ စာအုပ်စီမံခန့်ခွဲမှုကို လက်ဖြင့်လုပ်နေရာက software ပြောင်းပေးတဲ့ system ပါ။ လက်ရှိ စာကြည့်တိုက်တွေက စာအုပ်ငှားခြင်း၊ ပြန်ပေးခြင်း၊ ဒဏ်ကြေးတွက်ခြင်းတွေကို စာရင်းစာအုပ်နဲ့ manual လုပ်နေရတာများပြီး အမှားများတယ်၊ အချိန်ကုန်တယ်။ ဒီ pain point ကို software နဲ့ဖြေရှင်းပေးတာက value proposition ဖြစ်ပါတယ်။

**ဖြေရှင်းပေးတဲ့ ပြဿနာများ:**

- စာအုပ်ဘယ်နှစ်အုပ်ရှိလဲ၊ ဘယ်သူ့ဆီရောက်နေလဲ ခြေရာခံရခက်ခြင်း
- ငှားရမ်းရက်ကုန်တာကို manual စစ်ရခြင်း (late fee တွက်ရခက်)
- Member စာရင်းနဲ့ history ကို paper-based နဲ့ ထိန်းရခြင်း
- Report (ဘယ်စာအုပ်အများဆုံးငှားလဲ) ထုတ်ရခက်ခြင်း

**ရောင်းချိုင်း/Target users:**

- ကျောင်း/တက္ကသိုလ် library staff (admin)
- ကျောင်းသား/ဝင်ရောက်သူများ (member)
- Librarian (day-to-day operator)

---

## ၂။ Core Actors (User Roles)

|Role|လုပ်ပိုင်ခွင့်|
|---|---|
|**Admin**|Staff account management, system settings, reports အားလုံးကြည့်ခွင့်|
|**Librarian**|စာအုပ် add/edit/delete, ငှားခြင်း/ပြန်ခြင်း process လုပ်ခွင့်|
|**Member**|စာအုပ်ရှာဖွေခြင်း၊ ကိုယ်ပိုင် history ကြည့်ခြင်း|

Login system တစ်ခုနဲ့ role-based access control (RBAC) ထားသင့်ပါတယ်။

---

## ၃။ Functional Requirements (Feature List)

### Book Management

- စာအုပ်အသစ် add (Title, Author, ISBN, Category, Publisher, Copies count)
- စာအုပ် update/delete
- Search (title, author, ISBN, category အလိုက်)
- Book status (Available / Borrowed / Reserved / Lost)

### Member Management

- Member registration (Name, ID, Contact, Membership type)
- Member profile update
- Member borrowing history ကြည့်ခြင်း

### Borrowing / Circulation

- Issue book (ငှားခြင်း) — due date auto calculate (ဥပမာ ၁၄ ရက်)
- Return book (ပြန်ပေးခြင်း) — late fee auto calculate
- Renew book (သက်တမ်းတိုးခြင်း)
- Reserve book (တန်းစီစောင့်ခြင်း) — book available ဖြစ်လာရင် notify

### Fine Management

- Late return fine auto-calculation (ရက်အလွန် x နှုန်းထား)
- Fine payment record

### Reports & Dashboard

- Most borrowed books
- Overdue books list
- Total books / members statistics
- Daily transaction log

### Admin

- Staff account create/manage
- System configuration (loan period, fine rate)

---

## ၄။ Non-Functional Requirements

- **Usability**: Swing UI ကို intuitive ဖြစ်အောင်၊ error message ရှင်းလင်းအောင်
- **Performance**: Book search fast ဖြစ်ရမယ် (indexed query)
- **Data integrity**: Book count နဲ့ borrowed count sync ဖြစ်နေရမယ်
- **Security**: Password hashing (BCrypt), SQL injection မဖြစ်အောင် PreparedStatement သုံးရမယ်
- **Maintainability**: Layered architecture ထားပြီး code ချဲ့ရလွယ်အောင် ဒီဇိုင်းလုပ်ရမယ်

## ၅။ System Architecture (Layered / MVC)

```
┌─────────────────────────────┐
│   Presentation Layer        │  ← Java Swing (JFrame, JPanel, JTable...)
├─────────────────────────────┤
│   Service / Business Layer  │  ← Business logic, validation
├─────────────────────────────┤
│   DAO Layer (Data Access)   │  ← JDBC, CRUD operations
├─────────────────────────────┤
│   Database                  │  ← MySQL / SQLite
└─────────────────────────────┘
```

**Package structure (ဥပမာ):**

```
com.library
 ├── model/          (Book, Member, Loan, Fine, Staff)
 ├── dao/            (BookDAO, MemberDAO, LoanDAO)
 ├── service/        (BookService, LoanService, FineService)
 ├── ui/             (LoginFrame, MainDashboard, BookPanel, MemberPanel)
 ├── util/           (DBConnection, Validator)
 └── Main.java
```

Layer တစ်ခုစီက တစ်ခုနဲ့တစ်ခု တိုက်ရိုက်မချိတ်ဆက်ဘဲ interface ကတဆင့်ဆက်တာက testability နဲ့ maintainability အတွက် အရေးကြီးပါတယ် — ဒါက object-oriented design ရဲ့ "loose coupling" principle ကို လက်တွေ့ကျင့်တာဖြစ်ပါတယ်။

## ၆။ Database Design (ER Model အကြမ်းဖျင်း)

**Tables:**

`Book`

- book_id (PK), title, author, isbn, category_id (FK), total_copies, available_copies, status

`Member`

- member_id (PK), name, email, phone, membership_date, membership_type

`Staff`

- staff_id (PK), username, password_hash, role

`Loan`

- loan_id (PK), book_id (FK), member_id (FK), issue_date, due_date, return_date, status

`Fine`

- fine_id (PK), loan_id (FK), amount, paid_status, paid_date

`Category`

- category_id (PK), category_name

**Relationships:**

- Book — Category: many-to-one
- Loan — Book, Loan — Member: many-to-one (loan history)
- Fine — Loan: one-to-one

## ၈။ Design Patterns ဘယ်နေရာတွေမှာ တွေ့မလဲ (သင်လေ့လာပြီးသားတွေနဲ့ ချိတ်ပေးမယ်)

သင် Creational, Structural, Observer, Strategy တွေ လေ့လာပြီးသားမို့ ဒီ project မှာ တိုက်ရိုက်အသုံးချလို့ရတဲ့ နေရာတွေ ညွှန်ပြပေးပါမယ်:

- **Singleton** → `DBConnection` class — database connection instance တစ်ခုတည်းသာ ရှိအောင် (connection pool မလိုအောင်ရိုးရှင်းတဲ့ project အတွက်)
- **Factory Method** → `DAOFactory` — BookDAO, MemberDAO စတဲ့ DAO object အမျိုးမျိုးကို create လုပ်ဖို့
- **DAO Pattern** (Structural-adjacent, GoF မဟုတ်ပေမယ့် enterprise pattern) → database access logic ကို business logic နဲ့ ခွဲပေးတာ
- **Observer** → Book status ပြောင်းသွားရင် (available ဖြစ်လာရင်) reservation queue ထဲက members ကို notify လုပ်ဖို့
- **Strategy** → Fine calculation — membership type အလိုက် fine rate မတူညီရင် (Student vs Staff) `FineStrategy` interface ခံပြီး algorithm ပြောင်းလို့ရအောင်
- **Facade** → `LibraryService` class တစ်ခုက BookService, LoanService, FineService တွေကို ခေါ်သုံးပြီး UI layer ကို simple interface တစ်ခုတည်း ပြသဖို့
- **Builder** → Complex `Loan` object တစ်ခု step-by-step ဆောက်ဖို့ (issue date, due date, member, book စတာတွေ)

ဒီ pattern တွေကို project ထဲမှာ တကယ်လက်တွေ့ code ရေးပြီး ကျင့်ကြည့်ရင် pattern သဘောတရားကို ပိုနက်နဲအောင် နားလည်လာမှာပါ။
