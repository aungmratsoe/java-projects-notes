## `slf4j-api` နဲ့ `logback-classic` Dependency သုံးနည်း

`System.out.println()` နဲ့ debug လုပ်တာက small script အတွက်တော့ ရပေမယ့်, production application မှာ log level ခွဲခြင်း (DEBUG/INFO/WARN/ERROR), file ထဲ auto-save ခြင်း, log rotation (daily file, size limit) စတာတွေအတွက် **logging framework** လိုအပ်ပါတယ်။ SLF4J က "interface" (facade) ဖြစ်ပြီး Logback ကတော့ actual "implementation" (engine) ဖြစ်ပါတယ် — ဒီနှစ်ခု ပေါင်းသုံးတာက Java logging မှာ industry-standard combination ဖြစ်ပါတယ်။

### ၁။ SLF4J vs Logback ကွာခြားချက်

- **SLF4J (Simple Logging Facade for Java)**: log call တွေရေးရာမှာ သုံးမယ့် **API/interface** ပဲဖြစ်ပါတယ်။ Actual log ဘယ်လိုရေးမလဲဆိုတာကို မဆုံးဖြတ်ပါဘူး။
- **Logback**: SLF4J interface ကို implement လုပ်ထားတဲ့ **actual logging engine** ဖြစ်ပါတယ် — log ကို console/file ဘယ်လို output လုပ်မလဲ၊ format ဘယ်လိုရေးမလဲ သတ်မှတ်ပေးတယ်။

ဒီလို facade + implementation ခွဲထားခြင်းရဲ့ အားသာချက်က နောင်တစ်ချိန် Logback ကနေ Log4j2 လို framework တစ်ခြားကို ပြောင်းချင်ရင် code ထဲက `import org.slf4j.Logger` ခေါ်ပုံတွေကို လုံးဝမပြောင်းဘဲ dependency ပဲပြောင်းလဲရုံနဲ့ ရနိုင်ပါတယ်။

### ၂။ Maven Dependency ထည့်ခြင်း

`pom.xml` ထဲ:

```xml
<dependencies>
    <dependency>
        <groupId>org.slf4j</groupId>
        <artifactId>slf4j-api</artifactId>
        <version>2.0.16</version>
    </dependency>
    <dependency>
        <groupId>ch.qos.logback</groupId>
        <artifactId>logback-classic</artifactId>
        <version>1.5.6</version>
    </dependency>
</dependencies>
```

`logback-classic` ကတော့ `logback-core` နဲ့ `slf4j-api` ကို transitive dependency အနေနဲ့ ကိုယ်တိုင် ဆွဲယူပါတယ် — `slf4j-api` ကို သီးခြားထပ်ထည့်ဖို့ မလိုပေမယ့်, version conflict မဖြစ်စေဖို့ explicit ထည့်ထားတာက ပိုစိတ်ချရပါတယ်။ `pom.xml` save ပြီးရင် NetBeans project ပေါ် right-click → **Reload Project** နှိပ်ပါ။

### ၃။ Logback Config File (`logback.xml`)

`src/main/resources/logback.xml` ဆိုပြီး ဖိုင်အသစ်ဖန်တီးပါ (NetBeans Projects panel ထဲမှာ **Other Sources → src/main/resources** အောက်မှာ right-click → New → Other → XML):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>

    <!-- Console ထဲ log ပြသရန် -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- File ထဲ log သိမ်းရန် (daily rotation ပါ) -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/qrcode-app.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <fileNamePattern>logs/qrcode-app.%d{yyyy-MM-dd}.log</fileNamePattern>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <root level="INFO">
        <appender-ref ref="CONSOLE" />
        <appender-ref ref="FILE" />
    </root>

</configuration>
```

`%d` = date/time, `%thread` = thread name (RMI concurrent client lesson အတွက် အထူးအသုံးဝင်ပါတယ်), `%-5level` = log level, `%logger{36}` = class name (truncated), `%msg%n` = actual message + newline.

`<root level="INFO">` က default log level ကို သတ်မှတ်ပါတယ် — `DEBUG` level log တွေကို ignore လုပ်ပြီး `INFO` အထက် (`INFO`, `WARN`, `ERROR`) ကိုပဲ output ထုတ်ပါလိမ့်မယ်။

### ၄။ Class ထဲမှာ Logger သုံးပုံ

```java
package com.ams.qrcode.service;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class WeatherService {

    // class name ကို logger name အဖြစ်သုံးတာက convention ဖြစ်တယ် - log ထဲမှာ ဘယ် class ကနေ log ဆွဲထားလဲ သိလွယ်စေတယ်
    private static final Logger logger = LoggerFactory.getLogger(WeatherService.class);

    public WeatherResponse fetchWeather(String city) {
        logger.info("Weather data ရယူနေသည်: city={}", city);

        try {
            // ... API call logic
            logger.debug("API response ရရှိသည်: statusCode={}", 200);
            return weatherResponse;
        } catch (IOException e) {
            logger.error("Weather data ရယူရာတွင် error ဖြစ်ပွားသည်", e); // exception object ကို ပါတင်ပေးလို့ stack trace အပြည့်ပါတယ်
            throw new RuntimeException(e);
        }
    }
}
```

**`{}` placeholder အသုံးပြုပုံ**: `logger.info("city={}", city)` လို့ရေးတာက `"city=" + city` string concatenation ထက် ပိုကောင်းပါတယ် — log level `INFO` disable ထားရင် (`DEBUG` calls တွေဆိုပါစို့) string concatenation ကို လုံးဝ **evaluate မလုပ်တော့ပါ**, performance ကောင်းစေပါတယ်။

### ၅။ Log Level များ (အသုံးဝင်ပုံအလိုက်)

```java
logger.trace("အသေးစိတ်ဆုံး debug info - loop ထဲက value တစ်ခုချင်း");
logger.debug("Development အတွက် debug info - method entry/exit, variable values");
logger.info("ပုံမှန် application flow - 'Server started', 'User logged in'");
logger.warn("ပြဿနာဖြစ်နိုင်ချေရှိတဲ့ အခြေအနေ - deprecated method ခေါ်တယ်, retry ဖြစ်တယ်");
logger.error("Error ဖြစ်ပွားခဲ့တယ် - exception catch, operation fail");
```

Level order: `TRACE < DEBUG < INFO < WARN < ERROR`. Config ထဲ `<root level="INFO">` ဆိုရင် `TRACE`/`DEBUG` calls တွေက output ထဲ ထွက်မလာတော့ပါဘူး — development လုပ်နေတုန်း `DEBUG` ပြောင်းထား, production release မှာ `INFO` ပြန်ပြောင်းလို့ရပါတယ်.

### ၆။ RMI Project (Server/Client) မှာ လက်တွေ့သုံးနည်း

Multi-client RMI server ဆိုရင် ဘယ် client ကနေ ဘယ် operation ခေါ်လဲဆိုတာ track လုပ်ဖို့ အရေးကြီးပါတယ်:

```java
public class StudentServiceImpl extends UnicastRemoteObject implements StudentService {

    private static final Logger logger = LoggerFactory.getLogger(StudentServiceImpl.class);

    @Override
    public synchronized void addStudent(Student student) throws RemoteException {
        logger.info("Student ထည့်သွင်းနေသည်: id={}, thread={}",
                student.getStudentId(), Thread.currentThread().getName());
        try {
            // ... DB insert logic
            logger.info("Student ထည့်သွင်းပြီးပါပြီ: id={}", student.getStudentId());
        } catch (Exception e) {
            logger.error("Student ထည့်သွင်းရာတွင် error: id={}", student.getStudentId(), e);
            throw new RemoteException("Add student failed", e);
        }
    }
}
```

Multi-thread RMI server ဖြစ်တာကြောင့် `%thread` pattern ပါတဲ့ log format က ဘယ် client thread ကနေ ဘယ် request ခေါ်ခဲ့လဲဆိုတာ log file ထဲမှာ ခွဲခြားကြည့်ရလွယ်စေပါတယ်။

### ၇။ Swing UI ထဲမှာ Exception Log ချိတ်ဆက်ခြင်း

```java
private void btnSaveActionPerformed(java.awt.event.ActionEvent evt) {
    try {
        // ... save logic
        logger.info("Form data save လုပ်ပြီးပါပြီ");
    } catch (Exception e) {
        logger.error("Form save error", e); // file ထဲ full stack trace သွားသိမ်းမယ်
        JOptionPane.showMessageDialog(this, "Save မအောင်မြင်ပါ"); // user ကို ရိုးရှင်းတဲ့ message ပဲပြမယ်
    }
}
```

User ကို technical stack trace ပြမယ့်အစား, log file ထဲ full detail သိမ်းထားပြီး UI မှာတော့ user-friendly message ပဲပြသင့်ပါတယ် — debug လုပ်ချင်ရင် log file ကိုပြန်ဖတ်လို့ရပါတယ်။
